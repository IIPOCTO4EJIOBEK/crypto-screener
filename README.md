# crypto-screener

ИИ-ассистент для поиска монет и точек входа: скринер по формациям и
плотности стакана, база данных, RAG по методике, предложения входа с
описанием стратегии и её отработки.

Проект личный, приватный. Торговля идёт через **Tiger.com Broker** —
прослойку-агрегатор над Binance, Bybit, OKX, Hyperliquid, Bitget, Gate.

| Таймфрейм формаций | измерены 5m/15m/1h/4h/1d. Прежний «значимый плюс» `trendline_bounce` (1h +0.911 R) оказался артефактом правила входа: бэктест засчитывал сделки, до входа которых цена не возвращалась. С проверкой исполнения на тех же окнах плюсов **нет ни одного**: `trendline_bounce` 1h −0.424 R (n=57), 15m −0.875 R (n=58, значимо в минус) (`docs/research/18`, `20`) |

Главное здесь не список источников, а то, что скринер работает, но измеренная
ожидаемость формаций после издержек отрицательна. Инструмент показывает это
числом, а не обещанием, и не подбирает числа так, чтобы выглядело лучше.

Тренд-фильтр — единственное, что издержки пережило, но и у него числа
скромные: превышение над простым удержанием рынка порядка 0.13 Sharpe, а
просадка −79 % делает правило непригодным без управления размером позиции.
Скачок до Sharpe 1.24 — это завышение отбора выживших, и оно измерено
отдельно: на составе, собранном по дате листинга, те же числа падают вдвое
(`docs/research/16`, §9). Срок жизни эффекта тоже измерен: он держится один-два
дня после сигнала, а при задержке в три дня различия с рынком нет вовсе
(§13) — то есть исполнение обязано быть автоматическим, иначе торговать нечем.

## Что важно понимать

1. **Ключ не нужен для скринера.** Стаканы, свечи и лента сделок —
   публичные данные. Приватный ключ требуется только под баланс и позиции,
   это отдельный слой.
2. **Данные берутся напрямую, а прокси мешает.** Прежняя запись «Binance
   недоступен из РФ» (451) была перевёрнута: 451 приходит на запрос **через
   прокси** — он стоит в США, а Binance закрывает США. Напрямую спот, перп и
   публичный market data Binance отвечают 200, Bybit тоже (403 у него — та же
   история с прокси). Скринер строит на живых данных Binance, Bybit и OKX, с
   единым интерфейсом: источник подменяем.
3. **Источник истины — перпетуал USDT-M, спот — контрольный ряд.** Измерение,
   живые свечи и стакан скринера идут с `fapi.binance.com`; спот остаётся,
   чтобы видеть базис. Это не одно и то же: 30.09.2026 перп шёл на ~0.043 %
   ниже спота, а по объёму BTC перп больше спота в 6.9 раза.
4. **Стратегия описывается правилами, а не настройками.** У каждой формации
   есть определение, критерии подтверждения, вход, стоп, цель и условие
   отмены — они лежат в `src/analysis/` и проверяются тестами.
5. **Числа считает код, а не модель.** Расчёты уровней, плотности,
   доходности и риска выполняются в коде; языковая модель объясняет
   результат и формулирует предложение, но не считает сама.

## Живой контур

Три шага, каждый запускается из корня проекта модулем — `PYTHONPATH` не нужен.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests/ -q          # весь набор, меньше секунды
```

```bash
# 1. накопить живые данные: свечи, стакан (цикл раз в 60 с, копит в data/screener.db)
.venv/bin/python -m tools.live.collect --once      # один круг
.venv/bin/python -m tools.live.collect --loop 60   # то же по кругу, раз в минуту

# 2. измерить ожидаемость формаций по архиву и записать её в базу
#    (порядка часа на 8 монет × 3 таймфрейма: работа растёт как n²/шаг,
#     подробности — в комментарии к STEP_BY_TF). Сделка засчитывается, только
#     если цена дошла до входа (docs/research/20); старое правило — --old-entry-rule
.venv/bin/python -m tools.live.refresh --days 45

# 3. отранжировать сегодняшние сигналы по измеренному R после издержек
.venv/bin/python -m tools.live.screen --db data/screener.db --html /tmp/screen.html
```

Отчёт по издержкам отдельно, если нужно посмотреть, сколько именно съедает
тариф при разных стопах:

```bash
.venv/bin/python -m tools.backtest_costs --symbols BTCUSDT ETHUSDT --tfs 5m 1h
```

Порядок обязателен: скринер сам ничего не считает. Он читает измерение из
`formation_stats`, и на пустой таблице честно печатает «сигналов N, из них с
измерением 0», а не подставляет уверенность детектора вместо ожидаемости.

Рядом с числами на странице стоят оговорки, без которых они читаются как
больше, чем есть. Измерение считает формацию на всём префиксе свечей и по
срезам (раз в столько-то свечей), а скринер ищет её на последних 300 свечах
базы. «n» — это сделки по всем монетам измерения сразу, а не по монете этой
строки. И плюсовая формация в таблице не значит, что она сработала сегодня:
итог считает эти два набора раздельно, а не подставляет один вместо другого.

Издержки берутся по верхней границе тарифа, а не по удобной нижней: комиссия
0.05 % за сторону — это USDT-M VIP 0 без скидок (с оплатой в BNB было бы
0.045 %), проскальзывание 1 б.п. — константа, а не замер, поэтому в отчёте
рядом с каждой монетой стоит фактический спред: у BTC он 0.01 б.п., у ADA в
те же сутки 4 б.п., и там константа издержки занижает. Фандинг считается по
фактическим начислениям перпетуала, с их настоящим интервалом.
