# Торговый контур: тренд-фильтр от бумаги до живого счёта

Дата: 04.10.2026. Это первый слой проекта, который ставит заявки. Скринер
формаций сюда не входит: после проверки исполнения (`docs/research/20`)
ни одна формация с нормальной выборкой не осталась в плюсе, торговать по ним
нечем. Бот торгует единственное правило, пережившее издержки, — long-only
тренд 28/5 на дневных барах (`docs/research/16`).

## Что бот делает

Раз в сутки, сразу после закрытия дневной свечи (00:05 UTC, 03:05 МСК):

1. берёт дневные свечи восьми монет (по умолчанию — перпетуал Binance, как в
   бэктесте; только закрытые бары);
2. считает моментум за 28 дней; монеты с плюсом — в портфель равными весами,
   остальное — в кэше;
3. раз в 5 дней (день решения привязан к календарю) переводит позиции в
   целевые веса рыночными заявками; пропущенный день решения догоняет;
4. каждый день пересчитывает капитал и проверяет **стоп по просадке**: капитал
   ниже пика больше чем на 35 % — продаёт всё и встаёт (файл `HALT`);
5. пишет всё в журнал (`data/trade/<режим>-<рынок>/journal.jsonl`) и, если
   задан Telegram, присылает сообщение о сделках, проблемах и остановке.

## Три режима, по порядку

| Режим | Что происходит | Ключ |
|---|---|---|
| `paper` (по умолчанию) | заявки не отправляются; цена исполнения считается по **живому стакану** проходом по уровням, плюс комиссия тейкера | не нужен |
| `testnet` | настоящие заявки на тестовой сети Binance, деньги ненастоящие | тестовый, с testnet.binance.vision |
| `live` | настоящие заявки на счёте | ключ Binance (из Tiger) с правом торговли |

Живой режим заблокирован тремя замками сразу: `--mode live`, флаг
`--i-understand-real-money` и `TRADE_LIVE=yes` в `.env`.

**Порядок перехода.** Бумага идёт первой и идёт долго: правило решает раз в
5 дней, за месяц это 6 решений. Смысл бумажного прогона — сравнить живое
исполнение с бэктестом: проскальзывание от середины стакана (в бэктесте — 1
б.п. константой), комиссию и поведение капитала. Переход на живой счёт —
решение человека после того, как журнал бумаги показан, и только малым
бюджетом (`--capital`).

## Команды

```
python -m tools.trade.run --plan                 # сигнал и заявки сейчас, ничего не исполняет
python -m tools.trade.run                        # бумажный шаг
python -m tools.trade.run --status               # капитал, позиции, среднее проскальзывание
python -m tools.trade.run --check-key live       # права ключа: торговля, вывод, IP — без заявок
python -m tools.trade.run --mode testnet         # шаг на тестовой сети
```

Расписание на VM (`crontab -e`), время в UTC:

```
5 0 * * * cd ~/Скринер && .venv/bin/python -m tools.trade.run >> data/trade/cron.log 2>&1
```

## Несколько ботов: спот и фьючерсы каждый день

Если есть `data/trade/profiles.json`, запуск без аргументов прогоняет все
профили по очереди. Так один и тот же таймер ведёт сразу несколько ботов:

```
[[], ["--market", "future", "--holding", "1"],
 ["--market", "future", "--holding", "1", "--side", "longshort"]]
```

Первый профиль — спот с ребалансом раз в 5 дней, второй — фьючерсы USDT-M с
ежедневным ребалансом, третий — фьючерсы, где бот по каждой монете сам выбирает
сторону: рост за 28 дней — лонг, падение — шорт (`--side longshort`). Журналы
раздельные (`paper-spot/`, `paper-future/`, `paper-future-longshort/`).
Сумма позиций по модулю не больше капитала, плеча нет; переворот — закрытие
(reduceOnly) и открытие заново.
На фьючерсах бумажный бот списывает фандинг по фактическим начислениям Binance
с прошлого шага (лонг платит при положительной ставке). Плечо — 1. Про шорт честно: в бэктесте шорт по тому же правилу сам по себе
дал −92 % (`docs/research/16`, §3); вариант лонг+шорт — Sharpe 1.22 и просадка
−52 % против 1.24 и −76 % у только лонга, то есть шорт не добавляет доходности,
а только срезает просадку на падениях. Плечо не проверялось. Ежедневный ребаланс в бэктесте — L28 H1: Sharpe 1.22 против 1.24
у H5 на восьмёрке, оборот 99 против 36 капиталов в год.

## Страница бота

После каждого шага бот пересобирает страницу `data/trade/<режим>-<рынок>/bot.html`:
описание правила, капитал и доходность против рынка (те же монеты, равные веса),
просадка, комиссии, проскальзывание, портфель, последний сигнал, все сделки и
сверка с числами бэктеста. Вторая копия — по `--page-out` или `TRADE_PAGE_OUT`
(например, в папку, которую раздаёт веб-сервер скринера). Вручную:
`python -m tools.trade.page`.

## Ключи и `.env`

Ключи живут только в `.env` на машине, где идёт бот (в git он не попадает).
Образец — `.env.example`. Перед живым режимом:

- `--check-key live` должен показать `enableSpotAndMarginTrading: True` и
  `enableWithdrawals: False`. Ключ с правом вывода боту не нужен и опасен.
- Ключи, переданные раньше в переписке, считаются скомпрометированными
  (`docs/00-состояние.md`, §5): для торговли выпустить **новый** ключ в
  кабинете Tiger, с привязкой к IP машины, где идёт бот.
- Биржа старого ключа так и не подтверждена: Binance-проверка упиралась в 451
  через прокси. С VM (прямой выход) `--check-key` ответит сразу.

## Лимиты риска

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--capital` | 1000 (или `TRADE_CAPITAL`) | бюджет бота; монеты, купленные руками, бот не видит и не продаёт |
| `--max-drawdown` | 0.35 | стоп: всё продать и встать; снимается только руками (удалить `HALT`) |
| `--max-coin-weight` | 1.0 | потолок веса монеты |
| `--max-gross` | 1.0 | доля капитала в рынке; плеча нет никогда |

## Что не проверено и чем бот отличается от бэктеста

- **Стоп по просадке бэктестом не проверен.** В истории правило проходило
  −76 % (восьмёрка) и −79 % (состав по дате), то есть стоп 35 % сработал бы
  — и остановил бы бота до восстановления. Это сознательный выбор: при такой
  просадке торговать без стопа нельзя, но его цена в доходности не измерена.
- **Спот вместо перпетуала.** Сигнал считается по перпетуалу (как в
  измерении), исполнение по умолчанию — на споте: без плеча, без ликвидации,
  без фандинга. Комиссия спота выше (0.1 % против 0.05 %). `--market future`
  исполняет на перпетуале с плечом 1 и продажей только на закрытие.
- **Фаза дня решения** в бэктесте шла от начала панели, здесь — от календаря.
  Сетка документа 16 показывает плато по holding, но именно эта фаза отдельно
  не мерилась.
- **Сам эффект скромный**: над рынком около +0.13 Sharpe на честном составе,
  и в 2026 году правило в минусе вместе с рынком. Бумажный прогон нужен, чтобы
  увидеть, переносится ли он вообще, а не чтобы подтвердить прибыль.

## Бот по сигналам скринера (бумажный)

Второй бот торгует не тренд-фильтром, а формациями нашего скринера на 5m, 15m
и 1h по фьючерсам Binance, в лонг и в шорт. Код: `src/trade/intraday.py`
(правила сделки), `tools/trade/screener_bot.py` (запуск),
`tools/trade/screener_page.py` (страница). Заявки на биржу не уходят, живого
режима у этого бота нет.

Один круг:

1. сигналы — те же формации и то же ранжирование, что на странице скринера,
   прямо из базы скринера (открывается только на чтение);
2. выходы открытых позиций — по минутным свечам перпетуала: стоп (проверяется
   раньше цели в той же свече, гэп за стоп исполняется по открытию свечи),
   первая цель формации, истечение через 40 свечей таймфрейма сигнала;
3. входы — свежий сработавший сигнал (событие на последней или предпоследней
   свече), цена из живого стакана, она должна лежать между стопом и целью;
   одна позиция на монету, не больше `--max-open` (5) позиций, риск
   `--risk-pct` (1 %) капитала, доля одной позиции не больше капитал/5,
   плеча нет;
4. просадка 35 % от пика — файл `HALT`, новые входы прекращаются, открытые
   доводятся до выхода.

Варианты (каждый — свой каталог `data/trade/screener-…`):

    python -m tools.trade.screener_bot                         # все сигналы
    python -m tools.trade.screener_bot --trend tf              # только по тренду скринера на тф сигнала
    python -m tools.trade.screener_bot --policy measured       # только с измеренным плюсом
    python -m tools.trade.screener_bot --status

Тренд берётся из `trend-now.json` скринера (EMA9/EMA21; для сигнала 5m —
тренд 15m). Если файл старше 15 минут, бот с фильтром тренда новых входов не
делает. Без фильтра тренд всё равно записывается в сделку — для сверки.

Запуск по кругу без sudo — через crontab пользователя:

    */2 * * * * cd /opt/crypto-trade && flock -n /tmp/screener-bot.lock .venv/bin/python -m tools.trade.screener_bot >> data/trade/screener-bot.log 2>&1

Честно о шансах: в документе 20 после проверки исполнения ни одна формация с
нормальной выборкой не осталась в плюсе с учётом издержек. Этот бот — живой
замер того же вопроса; главная таблица на его странице — «живой R против
измеренного» по типам формаций.

### Ведение позиции и лимиты (всё под флагами, по умолчанию выключено)

Взято у рыночных ботов (3Commas, WunderTrading, Finandy; разбор —
`/mnt/project-files/research/torgovye-boty-chto-vzyat.md`). Без флагов бот
ведёт себя как раньше: стоп, первая цель формации, время.

| флаг | что делает |
|---|---|
| `--tp1 1 --tp1-frac 0.5` | первый тейк: половина позиции на +1 R |
| `--be-after-tp1` | после первого тейка стоп переносится на вход |
| `--breakeven 1` | стоп на вход при +1 R (без частичного закрытия) |
| `--trail 1.5` / `--trail-pct 0.01` | трейлинг-стоп в 1.5 R / в 1 % от лучшей цены |
| `--no-target` | без цели формации: выход стопом, трейлингом или по времени |
| `--stop-on-close` | стоп по закрытию минутной свечи, а не по касанию (меньше выбиваний шпилькой, но выход бывает хуже стопа) |
| `--daily-loss 0.03` | убыток за сутки МСК больше 3 % капитала — новые входы до конца суток стоп |
| `--cooldown 30` | после стопа по монете 30 минут её не брать |
| `--pause-after 3 --pause-min 60` | три убыточные сделки подряд — пауза всех входов на час |
| `--max-side 3` | не больше трёх позиций в одну сторону |
| `--funding` | фандинг за время сделки входит в её результат |
| `--notify` | входы, тейки и выходы — в Telegram |

Стоп сдвигается только по закрытой минутной свече и только в сторону уменьшения
риска; внутри свечи стоп проверяется раньше тейков. R сделки всегда считается от
начального риска.

### Несколько ботов одним cron и управление из Telegram

`data/trade/screener-profiles.json` — список наборов аргументов; запуск без
аргументов проходит их все, сигналы скринера считаются один раз:

    [["--name", "all"],
     ["--name", "all-trend-tf", "--trend", "tf"],
     ["--name", "managed", "--trend", "tf", "--tp1", "1", "--be-after-tp1",
      "--trail", "1.5", "--no-target", "--daily-loss", "0.03", "--cooldown", "30",
      "--pause-after", "3", "--max-side", "3", "--funding", "--notify"]]

Если в `.env` заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, перед кругом бот
читает команды из этого чата: `/status`, `/pause` (новые входы стоп, открытые
ведутся), `/resume`, `/closeall` (закрыть всё по рынку), `/help`. Те же действия
руками — файлы `PAUSE` и `CLOSEALL` в каталоге бота.
