# Формации: правила, по которым скринер их находит

Документ описывает **что реально делает код** `src/analysis/formations.py`:
по какой свечной картине детектор понимает, что перед ним именно эта формация,
откуда берётся вход, где ставится стоп, куда целится и при каком условии
разбор отменяется.

Это не пересказ методики из интернета и не описание того, «как должно быть».
Все числа — это значения констант из кода. Если порог есть в источнике —
он помечен; если это наша рабочая оценка, это сказано прямо.

Смежный документ — `docs/02-архитектура.md` (устройство скринера, слои, что
работает). Исследовательская база — `docs/research/03-formacii-i-otrabotki.md`
(маркеры `[A]`/`[B]`/`[C]`/`[?]` ниже оттуда).

---

## 1. Как читать документ и главная оговорка

### 1.1. Оговорка про пороги

У Digash (сервис, чью методику воспроизводит скринер) опубликованы
**названия формаций и метрики, но не пороги детекторов**. Известно, что
формаций 12, что цель считается как N×ATR от входа, что ATR — это ATR(14),
что провал — это ход против позиции «не больше 1 ATR» (см.
`docs/research/01-digash-i-skanery.md`, раздел 2.5). Но **какое падение
объёма считать всплеском, насколько узким должен стать диапазон, сколько
касаний нужно уровню — этого в источнике нет**.

Поэтому у каждого числа в документе стоит пометка:

| Пометка | Что означает |
|---|---|
| **источник** | значение взято из исследования `docs/research/03-formacii-i-otrabotki.md` и совпадает с ним |
| **оценка** | рабочее значение, подобранное так, чтобы формация находилась на живом рынке; в коде помечено комментарием «значения — оценка, а не данные Digash» |
| **граница** | крайние значения пришли из источника, промежуточные ячейки — наша интерполяция |

Пороги собраны в начале `formations.py` одним блоком (строки 42–59) именно
для того, чтобы их можно было менять в одном месте.

### 1.2. Из чего состоит разбор

Каждый детектор возвращает не «сигнал», а объект `Formation` с полями:

| Поле | Смысл |
|---|---|
| `kind` | машинное имя формации: `breakout`, `bounce`, `zakol`, `retest`, `density_bounce`, `structure_break`, `trendline_bounce`, `trendline_break`, `squeeze`, `volume_splash`, `impulse`, `absorption`, `liquidity_sweep`, `knife` |
| `title` | русское название для интерфейса |
| `direction` | `long` / `short` |
| `entry`, `stop`, `targets` | цены входа, стопа и целей (список, `targets[0]` — ближайшая) |
| `triggered` | `True` — вход можно брать сейчас; `False` — детектор выставил условие, а не позвал в сделку |
| `confidence` | 0…1, сколько условий сошлось |
| `reasons` | список строк: почему формация найдена |
| `invalid` | при каком условии разбор отменяется |
| `age_candles` | сколько закрытых свечей назад произошло событие |
| `style` | `scalping` / `swing` / `long` по таймфрейму (`STYLES`) |

Производные: `risk_pct` = `|entry − stop| / entry × 100` (расстояние до стопа
в процентах), `reward_pct` — то же до первой цели, `rr` = `reward_pct / risk_pct`,
`position_size(депозит)` = `депозит × RISK_PCT/100 ÷ (risk_pct/100)`, где
`RISK_PCT = 1.0` (% на сделку).

Группировка по таймфреймам (`STYLES`): скальпинг — `1m, 3m, 5m, 15m`;
среднесрок — `30m, 1h, 4h`; долгосрок — `1d`. Если таймфрейма нет в списке,
`style_of` возвращает `scalping`.

## 2. Общие правила для всех формаций

Это важнее списка формаций: без этих трёх правил ни один детектор не работает
как надо.

### 2.1. Событие считается по закрытым свечам

`_scan()` (обёртка, через которую прогоняются все детекторы) на каждой
итерации отрезает хвост ряда и передаёт детектору `candles[:end]`. При
`age = 0` это `candles[:-1]` — **последняя свеча отброшена**. Внутри детектора
`candles[-1]` — это последняя **закрытая** свеча.

Почему без этого пустой экран: последняя свеча ещё формируется, её закрытие,
максимум, минимум и объём меняются каждую секунду. Детектор, оценивающий
формацию по ней, принимает решение по незаконченным данным: событие то
появляется, то исчезает, а стоп ставится за экстремум, которого через минуту
уже нет.

### 2.2. Событие ищется в окне, а не на одной свече

`_scan` проходит по последним `EVENT_WINDOW = 3` закрытым свечам. Для каждой
итерации он отрезает от ряда `age + 1` свечей и заново прогоняет детектор:

```
age = 0 → candles[:-1]   событие на последней закрытой свече
age = 1 → candles[:-2]   событие на предыдущей
age = 2 → candles[:-3]   событие двумя свечами раньше
```

Найденной формации присваивается `age_candles = age`, а её `ts` — время
закрытия той свечи, на которой событие случилось. Если `end < 30`, окно
обрезано и перебор прекращается.

Почему без этого пустой экран: пробой уровня или отскок — **момент, а не
состояние**. Детектор, срабатывающий ровно на свече пробоя, попадает в неё
один раз и на одну итерацию; лента формаций обновляется раз в 30 секунд
(см. исследование, раздел 2.5) — к моменту обновления свеча уже закрыта, и
формация не показывается никогда. Окно из трёх свечей плюс `age_candles`
позволяют показать событие, случившееся до трёх свечей назад, и честно
сказать, сколько свечей назад это было.

### 2.3. Стоп внутри шума выбрасывается

После сводного прогона `detect_all` считает
`min_risk = max(0.1, MIN_RISK_NATR × NATR)` = `max(0.1, 0.5 × NATR)`
(в процентах), где NATR — `natr(candles, 14)`. Все разборы с
`risk_pct < min_risk` удаляются.

Почему без этого пустой экран точнее — «экран с мусором»: если стоп стоит
ближе половины NATR, он внутри обычного разброса свечи и будет сбит шумом или
спредом, даже когда направление угадано. Такой разбор бесполезен, и лучше его
не показывать.

### 2.4. Прочие общие правила сводного прогона

`detect_all` (и только он; детекторы по отдельности этих правил не применяют):

1. `if len(candles) < 40: return []`.
2. Прогон всех детекторов из `DETECTORS` через `_scan` с `btc=btc`.
3. `detect_density_bounce` вызывается **отдельно и без окна** — плотность это
   снимок стакана, а не событие на свече.
4. Дедупликация: на пару `(kind, direction)` остаётся формация с наименьшим
   `age_candles` (самая свежая).
5. Фильтр `min_risk` из 2.3.
6. Если `rr < 0.8`, `confidence` уменьшается на 0.15 и в `reasons`
   добавляется «цель ближе стопа — соотношение хуже 1:0.8».
7. Если `age_candles > 0`, в `reasons` добавляется «событие N свечей назад».
8. Сортировка по `(triggered, confidence, rr)` по убыванию, отдаётся
   `limit` (по умолчанию 12) лучших.

Уверенность везде считается функцией `_confidence(*parts)`, то есть
`round(min(1.0, max(0.05, сумма)), 2)`: сумма баллов за сошедшиеся условия,
зажатая в диапазон 0.05…1.00.

### 2.5. Что такое уровень в нашем коде (`levels.py`)

Формации на уровнях опираются на `horizontal_levels()`. Уровень — это
датакласс `Level`: `price`, `kind` (`support` / `resistance`), `touches`
(число касаний), `broken` (пробит ли), `first_ts`, `last_ts`.

Как он строится:

1. Ищутся локальные экстремумы `find_pivots()`. Экстремум в точке `i` —
   это максимум/минимум в окне `[i − span, i + span]`, где `span` —
   адаптивное окно. Точка попадает в список только если после неё прошло
   `max(skip_recent, span)` свечей: экстремум «подтверждается» только
   задним числом. По умолчанию `PIVOT_SPAN = 40`, `SKIP_RECENT = 20`.
2. **Адаптивное окно** (`adaptive_span`): при истории `n ≥ 800` окно равно
   `PIVOT_SPAN = 40`; при `n < 800` окно сужается до `max(10, min(40, n // 25))`.
   Это наша оценка: Digash ищет экстремумы окном 40 на истории в 1000 свечей;
   на короткой истории то же окно даёт всего 4–6 уровней на монету, чего мало
   даже для одного пробоя. На срезе в 300 свечей (прогон по истории) окно
   получается `300 // 25 = 12`.
3. Близкие экстремумы одного типа (`kind`) объединяются в один уровень, если
   расстояние между ними `≤ tol`, где `tol = level_tolerance_pct(tf) / 100`.
   Цена уровня пересчитывается как средневзвешенное по числу касаний,
   `touches` растёт.
4. Уровень помечается `broken = True`, если после него цена уходила за него
   больше чем на `tol` (для сопротивления — `high > price × (1 + tol)`).
5. Результат сортируется по расстоянию до текущей цены; берётся
   `max_levels`.

Детекторы передают `skip_recent` сами: `detect_breakout` — `2`,
`detect_bounce` — `5`, `detect_retest` — `1`. Для пробоя и ретеста нужны
свежие уровни, поэтому окно отсечки маленькое; для отскока уровень должен
быть устоявшимся.

**Допуск уровня** (`level_tolerance_pct`) — «граница»: на `1m` это 0.2 %, на
`1d` — 1.25 % (это из Digash), а промежуточные таймфреймы считаются линейной
интерполяцией по логарифму длительности:
`0.2 + (1.25 − 0.2) × log(минут) / log(1440)`. Например, `5m` ≈ 0.43 %,
`15m` ≈ 0.59 %, `1h` ≈ 0.79 %.

**Трендовые линии** (`find_trend_lines`) строятся иначе: из локальных
экстремумов перебираются тройки точек одного типа. Линия валидна, если все
три лежат на ней в пределах `tol = trend_tolerance_pct(tf)/100` (граница:
0.05 % на `1m`, 0.6 % на `1d`, промежуточные — интерполяция), и цена нигде
не пробивала линию сильнее допуска. Возвращается `(наклон за свечу, сдвиг,
касаний, "up"/"down")`, отсортированные по числу касаний.

`PIVOT_GAP = 8` — **линия соединяет только близкие по времени экстремумы**:
вторая точка тройки берётся не дальше чем через 8 экстремумов от первой,
третья — не дальше 8 от второй (всего используется не больше 64 последних
экстремумов, `pivots[-PIVOT_GAP * 8:]`). Обоснование наше: наклонная линия —
инструмент локальный, дальняя история держится горизонтальными уровнями, а не
линиями; без этого ограничения тройки находились бы через всю историю и линия
не имела бы отношения к текущему движению.

### 2.6. Что такое плотность в стакане (`density.py`)

`find_densities(ob)` ищет крупные лимитные заявки. Порог задаётся
**относительно самого стакана**, а не абсолютной суммой: заявка считается
крупной, если её объём `≥ OUTLIER_K × медианного уровня` из 50 лучших
уровней (`OUTLIER_K = 6.0`, `MIN_LEVELS = 8`). Дальше отсекаются заявки с
`notional < MIN_NOTIONAL = 50 000` и заявки ближе `MIN_DISTANCE_PCT = 0.1 %`
или дальше `MAX_DISTANCE_PCT = 3.0 %` от середины стакана. Первое — потому
что у лучшей цены крупный объём стоит всегда (это верх стакана, как уровень
он бесполезен), второе — потому что до такой заявки цена не дойдёт. Сверху
`top = 5` заявок, ближайшие к цене — первыми.

Настоящая заявка против спуфинга: за это отвечает `DensityTracker`, который
сопоставляет плотности между снимками стакана (одинаковой ценой считается
цена в пределах `tolerance_pct = 0.05 %`). Он накапливает: сколько снимков
заявка прожила (`snapshots`), максимальный и минимальный размер, сколько
объёма съедено (`eaten`), время жизни. В `detect_density_bounce` это
используется так: если заявка наблюдалась больше 3 снимков и её текущий размер
не меньше 0.9 от максимального — вероятно, это не спуфинг (+0.2 к уверенности);
если снимков не больше 2 — спуфинг исключить нельзя (−0.15).

Численная база спуфинга из исследования (раздел 2.2, работа `[S5, A]`):
подозрительные заявки стоят в среднем **7.45 б.п.** от середины, обычные —
**1.03 б.п.**, то есть настоящая крупная заявка живёт дальше от лучшей цены.
Отсюда и порог `MIN_DISTANCE_PCT = 0.1 %` = 10 б.п. Фильтр «объём ≥ 4500 USD»
из `[S5, A]` в коде заменён на `MIN_NOTIONAL = 50 000` — это **наша оценка**
(завышено для отсечки мелких заявок на спокойном рынке).

Оценка времени «съедания» заявки: `absorb_seconds()` =
`размер / (средний объём за 2 часа × 2) × 3600` — это формула Digash, число
условное.

### 2.7. Метрики, на которые ссылаются пороги (`metrics.py`)

| Метрика | Формула в коде | Где используется |
|---|---|---|
| `natr(candles, 14)` | среднее `TR` за 14 свечей ÷ текущее закрытие × 100, где `TR = max(high−low, |high−пред. закрытие|, |low−пред. закрытие|)` | фильтр `MIN_RISK_NATR`, пороги импульса и ножа, слом структуры |
| `volume_splash(candles, 20)` | объём последней свечи ÷ средний объём за предыдущие 20 | `SPLASH_MIN`, `SPLASH_STRONG` |
| `efficiency_ratio(candles, 20)` | `|закрытие за период − закрытие в начале| ÷ сумма модулей всех шагов` | порог `SQUEEZE_ER` |
| `narrow_range(candles, 7)` | `True`, если диапазон последней свечи ≤ минимального диапазона предыдущих 6 (NR7 у Крабела) | бонус к уверенности сжатия |
| `correlation(a, b)` | коэффициент Пирсона между лог-доходностями, шкала −100…+100 | `_btc_against` |
| `price_change(btc, 30)` | изменение цены BTC за 30 минут, % | `_btc_against` |
| `volatility_index`, `liquidation_index`, `funding_per_day` | есть в файле | **ни одним детектором не используются** |

**Проверка BTC против сделки** (`_btc_against`) работает только по двум
условиям: корреляция с BTC по модулю `≥ 50` и ход BTC за 30 минут против
направления (для лонга — падение). Если связь слабая, BTC не мешает. Штраф
`−0.25` (в объёмном всплеске и импульсе — `−0.20`) применяется к уверенности;
на саму формацию он не влияет. Влияет только на `breakout`, `bounce`,
`retest`, `volume_splash`, `impulse`; остальные детекторы принимают аргумент
`btc`, но не вызывают `_btc_against`.

## 3. Формации

Разделы идут в порядке, в котором детекторы перечислены в `DETECTORS`.
Пороговые константы приведены ровно так, как объявлены в коде.

### 3.1. Пробой уровня — `breakout`

Детектор `detect_breakout`. Русское название «Пробой уровня» (`title`).

**Условие срабатывания.** Нужно ≥ 60 свечей. Перебираются горизонтальные
уровни (`max_levels=20`, `skip_recent=2`, `include_broken=True`) и проверяется
смена стороны уровня на последней закрытой свече:

- сопротивление: `prev.close ≤ lv.price < last.close` → пробой вверх, `long`;
- поддержка: `prev.close ≥ lv.price > last.close` → пробой вниз, `short`.

Где `prev = candles[-2]`, `last = candles[-1]`. То есть пробой — это **одна
свеча, закрывшаяся за уровнем**, тогда как предыдущая закрылась по другую
сторону. Если цена после пробоя ушла от уровня дальше, чем
`3 × level_tolerance_pct(tf)` (в процентах от цены уровня) — разбор
отбрасывается как поздний.

**Вход.** `entry = last.close` (закрытие свечи пробоя). `triggered = True`.

**Стоп.**
- `long`: `stop = min(last.low, lv.price × (1 − tol))`;
- `short`: `stop = max(last.high, lv.price × (1 + tol))`,

где `tol = level_tolerance_pct(tf)/100`. То есть стоп — за минимум свечи
пробоя, но не ближе, чем за уровень с допуском.

**Цель.** Считается высота зоны конгестии `height = hi − lo` по 40 свечам
перед пробоем (`_box(candles[-41:-1])`, последняя свеча не входит). Цель
measured move:
- `long`: `lv.price + height`; `short`: `lv.price − height`.

Если выше/ниже текущей цены есть ещё уровень, его цена вставляется первым
элементом списка (`targets[0]`), так что ближайшая цель — это ближайший
уровень, а measured move становится второй целью. Если высота нулевая —
`lv.price × 1.01` (лонг) / `lv.price × 0.99` (шорт).

**Отмена (`invalid`).** «Закрытие свечи обратно за уровень `lv.price` или
всплеск объёма меньше `SPLASH_MIN` (2.0)×».

**Уверенность.** База `0.35`; `+0.15`, если `lv.touches ≥ MIN_TOUCHES` (2);
`+0.2`, если `volume_splash(candles, 20) ≥ SPLASH_MIN` (2.0); `+0.15`, если
свеча закрылась в сторону пробоя — для лонга положение закрытия в свече
`(close − low) / (high − low) > 0.66`, для шорта `< 0.34`; `−0.25`, если BTC
идёт против. Итог зажимается `_confidence` в 0.05…1.00.

**Источник или оценка.** Качественные критерии пробоя (подтверждение объёмом,
measured move как цель, отмена при возврате за уровень) — из CMT-материалов
`[S1, B]` (раздел 1.1 исследования). Порог объёма «≥ 2× среднего» оттуда же,
и он совпадает с `SPLASH_MIN = 2.0` — это **источник** (сам источник помечен
`[B]`, академического подтверждения нет). Ограничение «ушли не дальше
3 × допуска», веса уверенности и требование одного закрытия (а не «2+
закрытий» `[S1, B]`) — **наша оценка**.

### 3.2. Отскок и закол уровня — `bounce` / `zakol`

Детектор `detect_bounce`. Машинное имя зависит от того, был ли прокол:
`zakol` при проколе уровня, `bounce` без него. Русское название «Закол
уровня» / «Отскок уровня».

**Условие срабатывания.** Нужно ≥ 60 свечей. Уровни берутся с
`skip_recent=5` и **без** пробитых (`include_broken` по умолчанию `False`).
На последней закрытой свече проверяются три условия одновременно:

- `touched` — цена дотянулась до уровня в пределах допуска: для поддержки
  `last.low ≤ lv.price × (1 + tol)`, для сопротивления
  `last.high ≥ lv.price × (1 − tol)`;
- `holds` — уровень удержал: для поддержки `last.close > lv.price`, для
  сопротивления `last.close < lv.price`;
- `wick ≥ WICK_SHARE` (0.45) — доля хвоста в свече. Для поддержки
  `wick = (min(open, close) − low) / (high − low)`, для сопротивления
  `wick = (high − max(open, close)) / (high − low)`.

`pierced` (закол) — свеча не только коснулась, но и проколола уровень:
для поддержки `last.low < lv.price × (1 − tol)`, для сопротивления
`last.high > lv.price × (1 + tol)`.

**Вход.** `entry = last.close`. `triggered = True`.

**Стоп.** За экстремум касания с допуском:
- `long`: `stop = last.low × (1 − tol)`;
- `short`: `stop = last.high × (1 + tol)`.

**Цель.** Первая цель — противоположная проекция касания с коэффициентом 1.5:
- `long`: `lv.price + (lv.price − last.low) × 1.5`;
- `short`: `lv.price − (last.high − lv.price) × 1.5`.

Если есть ближайший уровень с другой стороны цены, он вставляется `targets[0]`.

**Отмена.** Для лонга — закрытие свечи ниже уровня, для шорта — выше.

**Уверенность.** `0.3 + (0.25 если закол, иначе 0.1) + min(wick, 0.8) × 0.25`;
`+0.1`, если `lv.touches ≥ MIN_TOUCHES` (2); `+0.1`, если
`volume_splash(candles, 20) ≥ SPLASH_MIN` (2.0); `−0.25` против BTC. Всё
зажимается `_confidence`.

**Источник или оценка.** Качественные критерии («касание + разворотная свеча,
подтверждающий объём, чем больше касаний — тем сильнее уровень») — из
трейдерской практики `[S7, C]`, `[S18, C]` (раздел 1.4). Определение закола
как ложного пробоя (прокол + возврат, сработали стопы) опирается на
вайкоффские spring/upthrust `[S14, A]` (раздел 1.3), но там критерии
качественные, чисел нет. `WICK_SHARE = 0.45` и коэффициент 1.5 для цели —
**наша оценка**.

### 3.3. Ретест уровня — `retest`

Детектор `detect_retest`. Русское название «Ретест уровня».

**Условие срабатывания.** Нужно ≥ 60 свечей. Берутся **только пробитые**
уровни (`include_broken=True`, `skip_recent=1`). Пятисвечный отрезок
`window = candles[-6:-1]` (то есть пять свечей до последней закрытой) должен
целиком лежать по другую сторону уровня: для бывшего сопротивления —
`все close > lv.price × (1 − tol)`, для бывшей поддержки —
`все close < lv.price × (1 + tol)`. Затем на последней закрытой свече:

- `touched` — возврат к уровню в пределах допуска (для сопротивления
  `last.low ≤ lv.price × (1 + tol)`, для поддержки
  `last.high ≥ lv.price × (1 − tol)`);
- `reversed_` — свеча закрылась обратно в сторону пробоя: для лонга
  `last.close > lv.price` **и** `last.close > last.open`; для шорта
  `last.close < lv.price` **и** `last.close < last.open`.

Нужны все три условия. Уровень, бывший сопротивлением, после пробоя работает
поддержкой → лонг; зеркально для шорта.

**Вход.** `entry = last.close`. `triggered = True`.

**Стоп.** Для лонга `min(last.low, lv.price × (1 − tol))`, для шорта
`max(last.high, lv.price × (1 + tol))`.

**Цель.** `last.close ± rng × 2`, где `rng = last.high − last.low`. Если есть
ближайший уровень с нужной стороны, он вставляется `targets[0]`.

**Отмена.** Закрепление цены за уровнем с обратной стороны (для лонга — ниже
уровня, для шорта — выше).

**Уверенность.** База `0.45` — самая высокая среди «графических» детекторов,
потому что формация требует подтверждения пробоя возвратом. `+0.15` при
`touches ≥ MIN_TOUCHES` (2); `+0.1` при `splash ≥ SPLASH_MIN` (2.0);
`−0.25` против BTC.

**Источник или оценка.** Признак «цена не закрывается обратно за уровень»
и цели «продолжение импульса» — из практики `[S2, C]`, `[S3]`, `[S4, C]`
(раздел 1.2). Все числа — **наша оценка**: исследование прямо говорит, что
численного критерия ретеста («объём ретеста не более X % от объёма пробоя»,
«глубина не более Y %») ни в одном источнике нет, различие проводится
качественно. Обратите внимание: код **не** проверяет, что объём на возврате
пониженный (как рекомендует источник) — проверяется только
`above and touched and reversed_`.

### 3.4. Отскок от плотности — `density_bounce`

Детектор `detect_density_bounce`. Русское название «Отскок от плотности».
Единственная формация, которая считается **по стакану**, а не по графику.

**Условие срабатывания.** Нужно ≥ 30 свечей и хотя бы одна плотность
(`find_densities(ob)` либо переданный список). Для каждой плотности:

- расстояние до середины стакана `|d.distance_pct| ≤ 0.5 %` (захардкожено,
  не вынесено в константу) — цена уже подошла к заявке;
- для бида `near = last.low ≤ d.price × (1 + tol)`, лонг; для аска
  `near = last.high ≥ d.price × (1 − tol)`, шорт. Если `near` не выполнено —
  плотность пропускается.

**Вход.** `entry = last.close`. `triggered = True`.

**Стоп.** За плотность с двойным допуском: для лонга
`stop = d.price × (1 − tol × 2)`, для шорта `stop = d.price × (1 + tol × 2)`.

**Цель.** Ровно одна цель по ту сторону плотности: для лонга
`d.price × (1 + tol × 3)`, для шорта `d.price × (1 − tol × 3)`.

**Отмена.** «Плотность исчезла из стакана или цена закрылась за ней — признак
спуфинга».

**Уверенность.** `0.3 + min(d.notional / 500 000, 0.3)` — масштаб заявки;
`+0.2`, если заявка прожила больше 3 снимков **и** её размер не меньше 0.9 от
максимального (`snapshots > 3 and d.size ≥ d.max_size × 0.9`) — «стоит на
месте и не уменьшается, не спуфинг»; `−0.15`, если снимков не больше 2
(«спуфинг исключить нельзя»). В `reasons` добавляется оценка времени
растворения заявки `~eat/60 мин`, если передан `avg_volume_2h_base`.

**Источник или оценка.** Идея, что спуфинг отличается от реальной стены
прежде всего дистанцией от лучших цен, — из `[S5, A]` (раздел 2.2); порог
`MIN_DISTANCE_PCT = 0.1 %` = 10 б.п. согласуется с измерениями источника
(7.45 б.п. у подозрительных, 1.03 б.п. у нормальных). Остальные числа —
**наша оценка**: порог близости 0.5 %, множители допуска 2 и 3 для стопа и
цели, порог ноционала 500 000 для уверенности. «Коэффициента поглощения» как
формулы в источниках нет (`[?]`).

**Важно:** в `detect_all` этот детектор вызывается с `ob` и `densities`,
которые передал вызывающий; если стакан не передан, список плотностей пуст и
детектор всегда возвращает пусто (см. раздел 5).

### 3.5. Слом структуры — `structure_break`

Детектор `detect_structure_break`. Русское название «Слом структуры».

**Условие срабатывания.** Нужно ≥ 80 свечей. Через `_swings(candles)`
(то есть `find_pivots` с `span = SWING_SPAN = 5`) находятся перегибы, от
которых берутся последние `STRUCTURE_MEMORY = 6` максимумов и 6 минимумов.
Нужно минимум по 2 тех и других.

Структура считается восходящей, если `highs[-1] > highs[-2]` **и**
`lows[-1] > lows[-2]`, нисходящей — если `highs[-1] < highs[-2]` **и**
`lows[-1] < lows[-2]` (сравниваются цены последних двух перегибов каждого
типа).

- при восходящей структуре и `last.close < последний минимум × (1 − tol)` —
  слом вниз, `short`;
- при нисходящей и `last.close > последний максимум × (1 + tol)` — слом
  вверх, `long`.

**Вход.** `entry = last.close`. `triggered = True`.

**Стоп.**
- слом вниз: `stop = highs[-1]` (последний максимум структуры);
- слом вверх: `stop = lows[-1]` (последний минимум структуры).

**Цель.**
- слом вниз: `[lows[-2], last.close − (stop − last.close)]` — предыдущий
  минимум и равное движение вниз;
- слом вверх: `[highs[-2], last.close + (last.close − stop)]`.

**Отмена.** Для слома вниз — «возврат цены выше сломанного минимума и
обновление максимума»; для слома вверх — «возврат цены ниже сломанного
максимума».

**Уверенность.** `_confidence(0.5, 0.1 если свеча закрылась в сторону слома)`,
то есть 0.5 или 0.6. Как и у остальных, может быть урезана при `rr < 0.8`.

**Дополнительный фильтр.** Если `risk_pct > 4 × NATR`, разбор не выдаётся
вообще: до стопа слишком далеко, это уже не слом структуры, а полноценный
разворот.

**Источник или оценка.** Сама логика (пробой последнего higher low при
восходящей структуре) — это CHoCH из SMC/ICT, описанный в трейдерской
практике `[S16, C]` (раздел 1.5). Важная оговорка оттуда же: BOS/CHoCH —
не академическая концепция, формального определения «свинга» нет, параметр
алгоритма произволен. В коде этот параметр — `SWING_SPAN = 5`,
`STRUCTURE_MEMORY = 6`, порог `4 × NATR` — **наша оценка**. Отдельно:
`_swings` вызывает `find_pivots` с `span = 5`, но `skip_recent` остаётся
по умолчанию `20`, поэтому последние 20 свечей в поиске перегибов не
участвуют. Комментарий в докстринге `_swings` («последние `span` свечей не
участвуют») этому не соответствует — фактически отсекается 20 свечей.

### 3.6. Наклонки — `trendline_bounce` / `trendline_break`

Детектор `detect_trendline_event`. Русские названия «Отскок от наклонной»
и «Пробой наклонной».

**Условие срабатывания.** Нужно ≥ 80 свечей. Через `find_trend_lines`
(`max_lines=6`, `skip_recent=1`) строятся наклонные линии — тройки
экстремумов одного типа, лежащие на прямой в пределах допуска. Для каждой
линии считается её цена на текущей свече `at_now = slope × i + offset` и на
предыдущей `at_prev = slope × (i − 1) + offset`.

- восходящая линия (`kind == "up"`, построена по минимумам):
  - отскок, `long`: `at_now × (1 + tol) ≥ last.low` **и**
    `last.close > at_now` **и** `|last.low − at_now| / at_now ≤ 3 × tol`;
  - пробой вниз, `short`: `prev.close > at_prev` **и**
    `last.close < at_now × (1 − tol)`;
- нисходящая линия (`kind == "down"`, по максимумам) — зеркально:
  - отскок, `short`: `last.high ≥ at_now × (1 − tol)` **и**
    `last.close < at_now` **и** `|last.high − at_now| / at_now ≤ 3 × tol`;
  - пробой вверх, `long`: `prev.close < at_prev` **и**
    `last.close > at_now × (1 + tol)`.

Здесь `tol = trend_tolerance_pct(tf)/100`.

**Вход.** У отскока — **не закрытие свечи, а сама линия**: `entry = at_now`.
Это прямо объяснено в комментарии кода: к закрытию цена уже отошла от линии,
и стоп пришлось бы ставить внутри шума. У пробоя — `entry = last.close`.
`triggered = True` у обоих.

**Стоп.**
- отскок от восходящей: `stop = at_now × (1 − buffer_pct)`;
- отскок от нисходящей: `stop = at_now × (1 + buffer_pct)`;
- пробой восходящей вниз: `stop = max(last.high, at_now × (1 + tol))`;
- пробой нисходящей вверх: `stop = min(last.low, at_now × (1 − tol))`.

**Буфер стопа** — ключевая деталь: `buffer_pct = max(tol, MIN_RISK_NATR ×
NATR / 100)` = `max(tol, 0.5 × NATR / 100)`. Комментарий в коде фиксирует,
почему: в бэктесте разбор с допуском 0.06 % от линии давал 1 % попаданий —
стоп сбивало первой же свечой, хотя направление угадывалось. Если
`buffer_pct ≤ 0`, детектор не выдаёт ничего.

**Цель.** Удвоенное расстояние от входа до стопа:
- отскок: `at_now + (at_now − stop) × 2` (лонг) / `at_now − (stop − at_now) × 2`
  (шорт);
- пробой: `last.close − (stop − last.close) × 2` (шорт) /
  `last.close + (last.close − stop) × 2` (лонг).

**Отмена.** Для отскока — «закрытие свечи за линией `at_now`». Для пробоя —
«возврат цены за пробитую линию».

**Уверенность.** У отскока `_confidence(0.35, min(touches, 5) × 0.06)`, у
пробоя `_confidence(0.4, min(touches, 5) × 0.06)`, где `touches` — число
экстремумов на линии (минимум 3).

**Источник или оценка.** Связь формации с наклонной линией и подразделение
пробоев на горизонтальный и по трендовой линии — из CMT-материалов
`[S1, B]` (раздел 1.1). Определение самой линии (тройка экстремумов,
допуск, проверка на пробой) — из документации Digash, воспроизведено в
`levels.py`. Числа `touches ≥ 3`, `PIVOT_GAP = 8`, `max_lines = 6`, множитель
3 для допуска касания и `buffer_pct` — **наша оценка**.

### 3.7. Проторговка (сжатие) — `squeeze`

Детектор `detect_squeeze`. Русское название в интерфейсе — «Проторговка»,
машинное имя — `squeeze`.

**Условие срабатывания.** Нужно ≥ 80 свечей. Сравниваются два окна:
`recent = candles[-20:]` и `prior = candles[-60:-20]`.

- `height / prior_height > SQUEEZE_RATIO` (0.55) → не сжатие, выход. То есть
  диапазон последних 20 свечей должен быть **уже 55 %** диапазона
  предыдущих 40.
- Волатильность не падала: если `natr(candles[-21:], 14) > natr(candles[-41:-21], 14) × 0.8`
  → выход.
- Коэффициент эффективности Кауфмана: если `efficiency_ratio(candles, 20) > SQUEEZE_ER`
  (0.65) → выход. При сжатии цена ходит туда-сюда и почти не двигается по
  итогу, поэтому ER низкий.

Если все условия прошли — формация выдаётся **в двух направлениях сразу**,
лонг и шорт.

**Вход.** Не сейчас, а на пробое границы сжатия, поэтому `triggered = False`:
- лонг: `entry = hi × 1.0005`, шорт: `entry = lo × 0.9995`.

**Стоп.** Противоположная граница сжатия без буфера: для лонга `stop = lo`,
для шорта `stop = hi`.

**Цель.** Проекция ширины сжатия: `entry + (hi − lo)` для лонга,
`entry − (hi − lo)` для шорта.

**Отмена.** «Цена вышла из диапазона в обратную сторону — сжатие разрешилось
против выбранного направления».

**Уверенность.** База `0.4`; `+0.15`, если `height / prior_height < 0.4`
(сжатие очень плотное); `+0.1`, если текущая свеча — NR7 (`narrow_range`
с `NR_PERIOD = 7`); `+0.1`, если `ER < 0.4`; `+0.15`, если средний объём в
`recent` выше, чем в `prior` («объём в сжатии не упал — идёт набор позиции»).
Если объём упал, добавляется обратная причина: «интерес к монете пропал,
пробой может быть ложным».

**Источник или оценка.** Единственная группа формаций с точными числами в
исследовании (раздел 1.7, `[S8, B]`): флаг сжатия `ER_t ≤ k_c`, где `k_c`
обычно **0.5–0.7** — отсюда `SQUEEZE_ER = 0.65` (**источник**). NR7 —
оттуда же (**источник**). Отношение диапазонов `SQUEEZE_RATIO = 0.55`
попадает в диапазон коэффициента контракции 0.5–0.7 из источника. Источник
подчёркивает: сжатие **не даёт ни направления, ни тайминга** и «первый пробой
часто неудачен» — поэтому детектор и отдаёт обе стороны с `triggered = False`.
Порог 0.4 для «очень плотного» сжатия, 0.8 для падения NATR и веса
уверенности — **наша оценка**.

### 3.8. Всплеск объёма — `volume_splash`

Детектор `detect_volume_splash`. Русское название «Всплеск объёма».

**Условие срабатывания.** Нужно ≥ 40 свечей.
`volume_splash(candles, 20) ≥ SPLASH_STRONG` (3.0). Если объём вырос, а цена
почти не сдвинулась (`|chg| ≤ ABSORB_MAX_MOVE`, 0.25 %) — это не всплеск, а
поглощение, и детектор молчит (его ловит `detect_smart_money`). Направление —
по знаку `chg = (close − open) / open × 100`.

Техническая деталь: свечой события берётся `candles[-1]`, но если у неё
`volume == 0`, код переключается на `candles[-2]`. При этом сам
`volume_splash` уже посчитан по `candles[-1]`. То есть при нулевом объёме
последней свечи коэффициент всплеска и свеча события берутся с разных свечей.

**Вход.** `entry = last.close`. `triggered = True`.

**Стоп.** За противоположный экстремум свечи всплеска: для лонга
`stop = last.low`, для шорта `stop = last.high`.

**Цель.** `last.close + rng × 2` (лонг) / `last.close − rng × 2` (шорт), где
`rng = last.high − last.low`.

**Отмена.** «Объём вернулся к обычному, а цена не продолжила движение».

**Уверенность.** `0.35 + min((splash − 3.0) / 10, 0.3)` — чем сильнее
всплеск, тем выше, но не более +0.3; `−0.2`, если BTC идёт против.

**Источник или оценка.** Понятие кульминации — вайкоффские selling/buying
climax `[S14, A]` (раздел 1.6), но у Вайкоффа определения качественные
(«наивысшая интенсивность», «extreme expansion»), **численного порога
всплеска в источниках нет** (`[?]`). `SPLASH_STRONG = 3.0` и множитель 10 в
бонусе — **наша оценка**. Код не отличает всплеск на тренде от кульминации
(после которой по Вайкоффу входить нельзя, нужен secondary test) — это
упрощение относительно источника.

### 3.9. Импульс — `impulse`

Детектор `detect_impulse` (`lookback = 5`). Русское название «Импульс».

**Условие срабатывания.** Нужно ≥ `lookback + 30` = 35 свечей. Отсчёт от
открытия свечи `candles[-6]`: `chg = (last.close − base.open) / base.open × 100`.
Требуется `|chg| ≥ IMPULSE_NATR × NATR` = `3.0 × natr(candles, 14)` —
то есть ход за 5 свечей больше трёх NATR. Направление — по знаку `chg`.

**Вход.** По откату от импульса, поэтому `triggered = False`:
`entry = last.close − size × 0.382`, где `size = last.close − base.open`.
Уровень 38.2 % — «золотое сечение» отката. Для лонга это ниже текущей цены,
для шорта — выше (потому что `size` отрицателен).

**Стоп.** `stop = base.open` — начало импульса.

**Цель.** `[last.close, last.close + size]`. Для лонга это закрытие импульсной
свечи и его удвоение; для шорта формула та же, но `size < 0`, поэтому обе
цели ниже.

**Отмена.** «Цена ушла глубже начала импульса — движение выдохлось».

**Уверенность.** `0.4 + min(|chg| / (IMPULSE_NATR × NATR) − 1, 1.0) × 0.2`;
`−0.2` против BTC.

**Источник или оценка.** В исследовании раздела про «импульс» как формацию
нет — есть пробои (1.1), всплески (1.6) и сжатие (1.7). Порог
`IMPULSE_NATR = 3.0`, откат 38.2 % и веса — **наша оценка** (откат — общая
практика Фибоначчи `[C]`). Логика «входить на откате, а не в конце импульса»
записана прямо в докстринге детектора.

### 3.10. Smart Money — `absorption` / `liquidity_sweep`

Детектор `detect_smart_money`. Выдаёт один из двух типов: «Smart Money:
поглощение» (`absorption`) или «Smart Money: сбор стопов» (`liquidity_sweep`).

**Условие срабатывания.** Нужно ≥ 60 свечей.

*Поглощение:* `volume_splash(candles, 20) ≥ SPLASH_STRONG` (3.0) **и**
`|chg| ≤ ABSORB_MAX_MOVE` (0.25 %) — крупный объём при почти нулевом ходе.
Направление — по положению закрытия в свече: `pos = (close − low) / (high − low)`,
лонг если `pos > 0.5`, иначе шорт.

*Сбор ликвидности:* через `_swings(candles[:-1])` берутся последние 5
минимумов и 5 максимумов (последняя свеча из поиска перегибов исключена).
Лонг, если `last.low < min(минимумов)` **и** `last.close > min(минимумов)` —
цена проколола минимум и вернулась выше. Иначе (через `elif`) короткий шорт,
если `last.high > max(максимумов)` **и** `last.close < max(максимумов)`.
За один проход возможен только один из двух.

**Вход.** `entry = last.close` у обоих. `triggered = True`.

**Стоп.**
- поглощение: `last.low` (лонг) / `last.high` (шорт);
- сбор стопов: `last.low` (лонг, за проколотый минимум) / `last.high`
  (шорт, за проколотый максимум).

**Цель.** Удвоенное расстояние до стопа:
- поглощение: `last.close + (last.close − stop) × 2` / зеркально;
- сбор стопов: то же.

**Отмена.** Поглощение — «цена ушла против набора на объёме выше
сегодняшнего». Сбор стопов (лонг) — «закрытие свечи ниже проколотого
минимума — стопы собраны, и падение продолжается»; зеркально для шорта.

**Уверенность.**
- поглощение: `_confidence(0.45, min(splash / 15, 0.25))`;
- сбор стопов: `_confidence(0.5, 0.1 если splash ≥ SPLASH_MIN)`.

**Источник или оценка.** Поглощение описано качественно в материалах по
дельте `[S10, C]` (раздел 1.6): большой лимит останавливает цену при
агрессии в одну сторону. Численной формулы «коэффициента поглощения» в
источниках **нет** (`[?]`), поэтому `ABSORB_MAX_MOVE = 0.25 %` и `SPLASH_STRONG = 3.0` —
**наша оценка**. Сбор стопов опирается на вайкоффские spring/upthrust
`[S14, A]` и на подтверждённую статистикой кластеризацию стоп-заявок за
круглыми числами (Osler, `[S15, A]`, раздел 1.3). Числа — **наша оценка**.

### 3.11. Ножи — `knife`

Детектор `detect_knives` (`lookback = 15`). Русское название «Ножи».

**Условие срабатывания.** Нужно ≥ `lookback + 20` = 35 свечей. На отрезке
`seq = candles[-15:]` считается `chg = (last.close − seq[0].open) / seq[0].open × 100`.
Требуется `chg ≤ −KNIFE_NATR × NATR` = `−5.0 × natr(candles, 14)` — падение
больше пяти NATR. Дополнительно: минимум `lookback × 0.7` = 10.5, то есть
**не меньше 11 свечей из 15** закрылись вниз (`close < open`) — откатов не
было.

Формация **предупреждающая**, поэтому `triggered = False`.

**Вход.** Условие, а не приказ: `entry = max(candles[-3:].high)` — максимум
последних трёх свечей, то есть первый разворот вверх. Пока закрытия выше
`entry` не случилось, входить нельзя.

**Стоп.** `stop = lowest × 0.999`, где `lowest = min(c.low for c in seq)` —
минимум всего падения, минус 0.1 %.

**Цель.** `entry + (entry − stop) × 2`.

**Отмена.** «Цена обновила минимум падения — разворот не состоялся, движение
продолжается».

**Уверенность.** `_confidence(0.3, 0.15 если |chg| > KNIFE_NATR × NATR × 1.5)`
— то есть 0.3, а при падении больше 7.5 NATR — 0.45.

**Источник или оценка.** «Падающий нож» — название формации у Digash
(FallingKnife), но в исследовании `docs/research/03-formacii-i-otrabotki.md`
прямого раздела о ней нет; «ловля ножа» упоминается только косвенно
(раздел 3.5, ловушка тонкого стакана). `KNIFE_NATR = 5.0`, доля красных
свечей 0.7, отступ стопа 0.999 — **наша оценка**. Детектор ловит только
падение (ножи вниз, разворот в лонг); зеркального «ножа вверх» нет.

## 5. Чего в коде нет

**«Структура рынка» (MarketStructure) — 12-е название из списка Digash, не
реализовано отдельным детектором.** В коде есть `detect_structure_break`,
который внутри определяет, восходящая структура или нисходящая
(`highs[-1] > highs[-2] and lows[-1] > lows[-2]`), но выдаёт карточку только в
момент её слома. Состояние «сейчас структура восходящая» наружу не отдаётся:
скринер показывает события, а не состояние. Формального определения «свинга»
для этой формации в источниках нет (раздел 1.5, `[S16, C]`), поэтому и
отдельный детектор не написан.

**Проторговка.** Отдельного детектора «проторговка» нет, но сама формация
реализована — это `detect_squeeze` с русским названием «Проторговка». В коде
проторговка формализована **как сжатие диапазона**: диапазон последних 20
свечей не больше 55 % предыдущих 40, упавшая волатильность и низкий
коэффициент эффективности Кауфмана. Важная оговорка: Digash-«Проторговка»
(Consolidation) шире, чем диапазон-сжатие — это может быть долгая
горизонтальная консолидация без обязательного сжатия амплитуды. В нашей
реализации это именно сжатие перед импульсом (раздел 1.7 исследования,
`[S8, B]`), и оно отдаётся с `triggered = False`. Поэтому в прогоне по истории
проторговки нет вообще.

**Данные стакана, которые не дошли до формаций.**

- Плотности — `density.py` работает, но в `detect_all` их нужно передать
  снаружи; без стакана `density_bounce` не сработает ни разу.
- Айсберг-заявки (`[S19, C]`, раздел 2.4) отдельно не детектируются. В
  `DensityTracker` есть только косвенный признак: заявка, которая долго стоит
  и не уменьшается, — «не спуфинг».
- `volatility_index`, `liquidation_index`, `funding_per_day` написаны в
  `metrics.py`, но ни одним детектором не используются.
- Открытый интерес (OI) в коде отсутствует полностью — функции для него нет.

**Профиль объёма (VPVR / POC / value area).** В исследовании помечен как
подтверждённый `[S9, B]` (раздел 1.8) и назван способом измерить силу уровня,
но в коде не реализован. Поэтому «сила уровня» у нас измеряется только числом
касаний `touches`, а не объёмом, проторгованным на уровне.

**Импульс и Ножи.** В исследовании отдельных разделов по этим формациям нет,
пороги `IMPULSE_NATR` и `KNIFE_NATR` — наша оценка, и обе формации отдаются
с `triggered = False`. «Нож вверх» (разворот в шорт после резкого роста) не
реализован.

**Лимит карточек.** `detect_all` возвращает не больше `limit` (по умолчанию
12) формаций и оставляет по одной на пару `(kind, direction)` — при обходе
большого списка монет это может отсекать формации, которые в отдельном
прогоне нашлись бы.
