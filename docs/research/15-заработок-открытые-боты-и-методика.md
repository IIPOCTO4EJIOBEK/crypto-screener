# Открытые решения для автоторговли криптой: что реально опубликовано и что перенять

Исследование под задачу владельца: скринер крипты на Python (формации на свечах + микроструктура стакана),
перпетуалы Binance USDT-M, taker 0.05 % за сторону (итого ~10 bp за круг). Ожидаемость формаций в замерах
вышла отрицательной у большинства — этот файл про то, как ту же задачу решали другие и что из их практики
измерения стоит забрать.

Метод: GitHub REST API (метаданные репозиториев — звёзды, язык, дата push, лицензия), официальная
документация проектов, README репозиториев, поиск через локальный SearXNG. Репозитории не клонировались.

## 0. Как читать пометки

- **ПРОВЕРЕНО** — я открыл репозиторий/страницу API/документацию и утверждение там действительно есть.
- **СО СЛОВ ДОКУМЕНТАЦИИ** — так написано в доке/README, но я не проверял это в коде или на данных.
- **НЕ ПОДТВЕРЖДЕНО** — найти подтверждение не удалось.
- **РЕКЛАМА** — внутри проекта есть продажа курсов/сигналов/подписок либо обзор-партнёрка. Числа доходности
  из таких источников считаю непроверяемыми.

Отдельно: **звёзды на GitHub ≠ прибыльность**. TradingAgents имеет 109 259★ (ПРОВЕРЕНО, GitHub API на 2026-09-30)
и при этом сам пишет, что результаты бэктестов не обязаны совпадать с опубликованными числами. А репозиторий
`grantreed1/Crypto-Order-Flow-Imbalance` с 0★ содержит самый честный разбор из найденного. Популярность —
это про качество инфраструктуры и размер сообщества, не про альфу.

## 2. Встроенные стратегии и честные результаты бэктестов

### Что лежит по умолчанию

**Freqtrade** (ПРОВЕРЕНО — листинг файлов репозитория `freqtrade-strategies`): ~50 стратегий в
`user_data/strategies/`. Своих «фирменных» нет; набор это учебные примеры и вклад сообщества:
`AlmgrenChrissStrategy`, `Bandtastic`, `BreakEven`, `CustomStoplossWithPSAR`, `Diamond`, `FixedRiskRewardLoss`,
`GodStra`, `Heracles`, `HourBasedStrategy`, `MultiMa`, **`PatternRecognition.py`**, `PowerTower`,
`Strategy001`–`005`, `Supertrend`, `SwingHighToSky`, `TWAPStrategy`, `TrendRiderStrategy`, `UniversalMACD`,
плюс большая папка `berlinguyinca/` (ADXMomentum, BbandRsi, BinHV27, BinHV45, CMCWinner, ClucMay72018,
CombinedBinHAndCluc, MACDStrategy, MultiRSI, Quickie, ReinforcedQuickie, Scalp и др.).

Прямо в нишу владельца попадает **`PatternRecognition.py`** — стратегия на свечных паттернах TA-Lib
(файл существует — ПРОВЕРЕНО; содержание и результаты я не разбирал — НЕ ПОДТВЕРЖДЕНО).

**Hummingbot** (ПРОВЕРЕНО — листинг каталогов): контроллеры делятся на три группы —
`market_making/` (`pmm_simple`, `pmm_dynamic`, `dman_maker_v2`), `directional_trading/`
(`bollinger_v1/v2`, `bollingrid`, `dman_v3`, `macd_bb_v1`, `supertrend_v1`, `ai_livestream`), `generic/`.
Скрипты включают готовые бэктесты: `backtest_bollinger_v2.py`, `backtest_grid_strike.py`,
`backtest_pmm_mister.py`, а также `screener_volatility.py`, `simple_vwap.py`, `v2_funding_rate_arb.py`.
В V1-наследии есть шаблон по статье **Avellaneda & Stoikov** (СО СЛОВ ДОКУМЕНТАЦИИ).

**Jesse** — стратегии пишет пользователь; в поставке примеры. Движок и метрики — сильная сторона.

**OctoBot** — grid, DCA, стратегии TradingView-сигналов, «AI» (СО СЛОВ README).

### Есть ли честные результаты

Коротко: **в самих проектах опубликованных результатов доходности нет — и это осознанная позиция.**

- Freqtrade в README репозитория стратегий (ПРОВЕРЕНО, цитаты): «These strategies are for educational purposes
  only», «provided as-is and without any warranty», «mostly should serve as a starting point». Конкретных
  чисел нет вообще. Пользователю прямо предлагают прогнать свой бэктест и сначала dry-run.
- Jesse в подвале документации (ПРОВЕРЕНО): «Be aware of overfitting!», «We do NOT guarantee profitable trading
  results in anyways», «Past performance is no guarantee of future results!».
- Hummingbot на странице стратегий вообще не касается прибыльности, комиссий мейкера и требований к капиталу
  (ПРОВЕРЕНО — я прочитал страницу `hummingbot.org/strategies/`; там про выбор V1/V2 и executors/controllers).
- NautilusTrader в доке по бэктесту заявлений о прибыльности не делает (ПРОВЕРЕНО).
- `tauricresearch/TradingAgents` (109k★) — пример честной оговорки: «Backtest results are not guaranteed to
  match any published figure» (СО СЛОВ README).

**Вывод для владельца:** если искать «готовые прибыльные настройки» в открытых репо — их там нет и это норма.
Зрелые проекты сознательно не публикуют доходность. Ценность — в движке и в инструментах проверки, не в настройках.

### Результаты С УЧЁТОМ издержек — где они есть

- **Freqtrade** (ПРОВЕРЕНО, `freqtrade.io/en/stable/backtesting/`): комиссии учитываются — «All profit
  calculations include fees, and freqtrade will use the exchange's default fees», `--fee` это «ratio, and will
  be applied twice (once for trade entry, and once for trade exit)». **Проскальзывание НЕ моделируется**:
  «All orders are filled at the requested price (no slippage) as long as the price is within the candle's
  high/low range». Спред не упоминается. Это дыра ровно там, где у владельца минус: формации на свечах
  обычно заполняются по цене, которой на реальном рынке уже нет.
- **Freqtrade** также считает `Mean profit p-value` и предупреждает (ПРОВЕРЕНО): «because backtesting and
  hyperopt evaluate many strategies, some will score a low p-value by chance alone» — то есть проблема
  множественных сравнений в доке признана прямым текстом.
- `davelamtrader/Strategy-Backtest-Orderbook-Imbalance-Pattern-...` (СО СЛОВ README): vectorbt, данные
  Tardis.dev (trades + orderBookL2), давление = логарифм отношения buy/sell pressure, порог
  `mean + 1.96·std` + условие «день вниз», фи: `fees=0.001`. **Проскальзывание не указано, численных
  результатов в README нет** — только качественное «aims to capture market inefficiencies». То есть
  издержки частично учтены, а результата нет → сравнивать не с чем.

## 3. Hummingbot отдельно: маркет-мейкинг

**Смысл.** Hummingbot — фреймворк для предоставления ликвидности: ты ставишь лимитные ордера с двух сторон,
зарабатываешь на спреде и/или на ребейтах мейкера, а платишь риском инвентаря и adverse selection
(тебя сносят именно когда рынок идёт против).

**Что есть.** Контроллеры `pmm_simple` (равномерные котировки вокруг мид-цены), `pmm_dynamic` (котировки от
индикатора), `dman_maker_v2`, направленные — `bollinger_*`, `supertrend_v1`, `macd_bb_v1` (ПРОВЕРЕНО —
листинг каталогов). Стратегии V1 включают реализацию Avellaneda & Stoikov (СО СЛОВ ДОКУМЕНТАЦИИ).

**Требования.** Конкретных цифр по капиталу/комиссиям в официальной доке я не нашёл (НЕ ПОДТВЕРЖДЕНО).
Из общей ниши (РЕКЛАМА, обзорные блоги, не первоисточники): отрицательные мейкер-комиссии/ребейты на
крупных биржах обычно достаются объёмам от $100M+/мес — то есть стратегия «жить на ребейтах» для
розницы в основном недоступна. Для владельца это значит: маркет-мейкинг на Binance USDT-M с его
maker 0.02 % / taker 0.05 % требует либо ребейта, либо спреда, устойчиво превышающего ~2 bp стоимости ног
плюс проскальзывание на сносе. Это не про «формации на свечах».

**Опубликованные данные о доходности кампаний.** Hummingbot Foundation раздаёт награды за ликвидность через
liquidity mining campaigns (есть даже разбор «demystifying-liquidity-mining-rewards»). **Публикации
устойчивой доходности кампаний я не подтвердил** (НЕ ПОДТВЕРЖДЕНО). Единственная цифра, которую Hummingbot
приводит на главной (СО СЛОВ README): «users have generated over $34 billion in trading volume across 140+
trading venues» — это **оборот, а не прибыль**; маркетинговая величина, к ожидаемости отношения не имеет.
Финансирование — Hummingbot Foundation и токен управления HBOT (ПРОВЕРЕНО, страницы whitepaper/FAQ);
это не продажа курсов, но и не независимая публикация результатов.

## 4. Проекты ровно в нише владельца (формации и плотность стакана)

Специализированных зрелых проектов **нет**. Ниша представлена отдельными репозиториями, часто с нулём звёзд.
Зато именно там нашлись самые полезные методологические вещи.

- **[grantreed1/Crypto-Order-Flow-Imbalance](https://github.com/grantreed1/Crypto-Order-Flow-Imbalance)**
  (0★, Jupyter, push 2026-03-12 — ПРОВЕРЕНО). Стресс-тест OFI-стратегии по шести биржам, данные tick +
  order book (parquet, из репо исключены по лимиту размера). Обработка: нормализация единиц, winsorization
  по 1/99 перцентилям, z-score. Сплит 40 % train / 60 % test, линейная регрессия на forward return, порог
  «top 5 % возможностей». Вывод автора (СО СЛОВ README): «a high-alpha signal severely undermined by
  directional risk and scaling limits». Числа: Net P&L $575 712 при max drawdown −$1.2M на OKX; без
  стоп-логики — «catastrophic −$62.3M drawdown»; масштабирование с 10 до 100 BTC упирается в «strict
  liquidity ceiling». ⚠️ Учтены ли эти числа нетто комиссий и проскальзывания — автор не подтверждает
  (НЕ ПОДТВЕРЖДЕНО), а сам вывод — «сигнал есть, торговать нельзя». Это ровно тот жанр честного отчёта,
  которого в нише почти нет.
- **[vankyle00/trading-models — OFI и затухание импакта](https://vankyle00.github.io/trading-models/docs/models/03-order-flow-imbalance-btc.html)**
  (ПРОВЕРЕНО, страница читалась). 8.7M aggTrades Binance → 4 320 минуток BTCUSDT, OFI = (V^B − V^S)/(V^B + V^S)
  по флагу `is_buyer_maker` (а не по угаданному tick rule), сглаживание 5 барами. Итог: **доходность −36 %,
  hit rate 29.7 %, Sharpe −86** на этом окне; поведение устойчиво на всех подокнах. Диагноз ценный: групповое
  запаздывание 5-барного сглаживателя = 2 минуты, а автокорреляция OFI затухает «on a seconds-to-minutes
  timescale» — то есть **сигнал умирает раньше, чем стратегия успевает войти**, и трейдер «systematically
  buying the local top of a buying impulse». Дополнительно посчитан drag издержек: разворот +1→−1 это 2
  единицы оборота, «2×7 = 14 bp». Рекомендация автора — пробовать контр-стратегию (fade имбаланса) и L2-OFI
  по Cont/Kukanov/Stoikov. Прямая аналогия с минусом владельца: **задержка формации против времени жизни края**.
- **[FETKlOkAn2/crypto-quant-platform](https://github.com/FETKlOkAn2/crypto-quant-platform)** (3★, Python,
  push 2026-08-23, Apache-2.0 — ПРОВЕРЕНО). Маленький, но методологически образцовый: vectorbt-бэктест,
  walk-forward с purge-gap и неперекрывающимися OOS-окнами, отчёт о деградации IS→OOS и стабильности
  параметров, **deflated Sharpe по Bailey & López de Prado**. Его демонстрация — лучший аргумент за DSR:
  200 стратегий с нулевым краем, обычный тест принял самую удачную на «99.5 %», DSR дал «43.7 % — rejected».
  Издержки берутся «from your risk configuration, not hardcoded». Заявленная позиция: «built to tell you
  when a strategy does not work» и «it usually does». Лицензия Apache-2.0 (ПРОВЕРЕНО).
- **[davelamtrader/…-Orderbook-Imbalance-Pattern-based-Cryptocurrencies-…](https://github.com/davelamtrader/Strategy-Backtest-Orderbook-Imbalance-Pattern-based-Cryptocurrencies-Screening-Trading-Strategy)**
  — см. §2, ближайший аналог «скринера по стакану», но без опубликованных результатов.
- **[alphabench/raptorbt](https://github.com/alphabench/raptorbt)** (47★, Rust, push 2026-09-10, MIT —
  ПРОВЕРЕНО): тиковый бэктест на любых OHLCV/tick массивах, включая basket/pairs/spread. Интересен как
  движок для тиковой точности, результатов стратегий не публикует.
- Общая тема GitHub `candlestick-patterns` — набор мелких сканеров («detects chart patterns, calculates
  historical probabilities from CSV or live crypto data»). Ни один не выглядит зрелым; популярных проектов
  в этой теме нет (ПРОВЕРЕНО по выдаче топика, отдельных звёздных репо не найдено).

**Что они делают иначе, чем владелец:** почти все переходят на **тиковые/L2 данные** (Tardis.dev, aggTrades),
считают **затухание сигнала во времени** до всякой стратегии, и явно фиксируют пороги издержек. И почти никто
не публикует «формация → вероятность» на свечах как самодостаточный результат — вероятно, потому что там
ожидаемость и упирается в издержки.

## 5. Сообщества и площадки: где результаты проверяют

- **[r/algotrading](https://www.reddit.com/r/algotrading/)** и его [wiki](https://www.reddit.com/r/algotrading/wiki/index/)
  — крупнейшая площадка, культура скептическая: принято публиковать результат **после издержек** («after
  $1 commission on either side and 2 ticks slippage» — типичная формулировка в постах, ПРОВЕРЕНО в выдаче),
  принято разбирать чужие числа и ловить look-ahead. Жанр «я бэктестил стратегию с YouTube на 400k просмотров
  и вот что вышло» — там же.
- **r/algotradingcrypto**, **r/algorithmictrading**, **r/quant** — уже, но те же правила: без методологии
  числа считаются шумом.
- **[QuantConnect Forum](https://www.quantconnect.com/forum/)** — обсуждения с реальными OOS-проверками;
  там же тема «the illusion of market-specific strategies» про иллюзию режимов.
- **Discord Hummingbot**, **Discord/GitHub Issues Freqtrade**, issue-трекер `freqtrade-strategies` — места,
  где чужой бэктест разбирают по коду.
- **[Freqle](https://freqle.org/)** — поисковик стратегий Freqtrade. ⚠️ **РЕКЛАМА**: это витрина/маркет
  стратегий, числа там непроверяемы.
- **[honest-backtest.com](http://honest-backtest.com/)** — аудит кода ботов. ⚠️ **РЕКЛАМА** (платная услуга),
  но сама идея «заказать аудит бэктеста» отражает норму: чужие результаты без аудита не принимаются.
- **Академическая база, на которую все ссылаются**: [Bailey & López de Prado, The Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf);
  [Stefan Jansen, ml4trading.io](https://ml4trading.io/second-edition/chapter/8/) и его репо
  [stefan-jansen/machine-learning-for-trading](https://github.com/stefan-jansen/machine-learning-for-trading)
  (21 123★, MIT — ПРОВЕРЕНО), где walk-forward и DSR разобраны с кодом.

**Как принято проверять чужие результаты (свод правил, выведенный из этих площадок):** числа — только нетто
комиссий и проскальзывания; обязательно out-of-sample holdout или walk-forward; указывать число испробованных
вариантов и корректировать на него (DSR/PBO); указывать стабильность параметров; сверять бэктест с live
(«reconciliation»); метрики, инвариантные к масштабу (hit rate, drawdown), для сравнения между работами.

## 6. Инструменты измерения, которые стоит перенять

По приоритету для проекта владельца:

1. **Поправка на множественные сравнения — DSR/PBO.** Это главное. Скринер формаций по определению
   перебирает сотни гипотез, и «полторы хорошие формации из 300» — это ожидаемый шум. Freqtrade сам
   предупреждает об этом в доке (см. §2), а `crypto-quant-platform` показывает наглядно: обычный тест дал
   99.5 %, DSR — 43.7 %. Перенять: считать **Deflated Sharpe** и **Probability of Backtest Overfitting**,
   а не «средний профит формации». Реализация есть в `mlfinlab`/`ml4t` и в репо Стефана Янсена.
2. **Walk-forward с purge-gap и embargo.** Тренировочное и тестовое окна не должны перекрываться и между ними
   нужен зазор (метки по свечам «протекают» через границу). Отчитываться о **деградации IS→OOS** и
   **стабильности параметров** (реализация: `crypto-quant-platform`).
3. **Издержки — из конфига, а не хардкодом, и с обеих сторон кругa.** Для владельца: 0.05 % taker × 2 = 10 bp
   за круг, плюс проскальзывание. В Freqtrade проскальзывания нет вообще — это известная дыра; при замерах
   формаций надо добавлять его руками (хотя бы фиксированные bp или тики).
4. **Аудит look-ahead и рекурсивности — прямо в код.** У Freqtrade есть готовые команды `lookahead-analysis`
   и `recursive-analysis` (ПРОВЕРЕНО): они пересчитывают индикаторы на усечённых данных и сравнивают значения.
   Идея переносится в любой Python-проект одной функцией. Важная оговорка из доки (ПРОВЕРЕНО): «Signals that
   are not triggered will not have been verified» — это даёт **ложные отрицания**; проверка не абсолютна.
   Типовые источники смещения по доке: `shift(-10)`, `iloc[]` в populate, агрегаты `.mean()/.min()/.max()`
   **без rolling-окна** (считают по всему датафрейму), `ta.MACD(..., 1)`.
5. **Измерять время жизни сигнала и сравнивать с задержкой индикатора.** Урок из OFI-разбора (vankyle00):
   сигнал затухает за секунды-минуты, а сглаживание внесло 2 минуты задержки → вход в локальный экстремум.
   Для формаций это значит: перед замерами ожидаемости надо измерить автокорреляцию отдачи после формации
   и убедиться, что она вообще переживает задержку распознавания + латентность ордера.
6. **Модель исполнения вместо «идеального филла».** Для стратегий на плотности стакана нужен L2-replay с
   очередью: NautilusTrader даёт «probabilistic fills» и работу с queue/aggressor sides (ПРОВЕРЕНО) —
   единственный из зрелых открытых движков, кто это умеет. Freqtrade для этой задачи не подходит.
7. **Хранение данных.** Единый формат (parquet), тиковые/L2 данные отдельно от свечей; в открытых проектах
   для L2 используют Tardis.dev (платно). У владельца уже есть публичные архивы Binance
   (`data.binance.vision`), чего для стакана не хватает — нужен либо свой сборщик L2, либо Tardis
   (сборщик стакана, кстати, есть в Hummingbot: `scripts/download_order_book_and_trades.py` — ПРОВЕРЕНО).
8. **Метрики, инвариантные к масштабу** (hit rate, drawdown, Sharpe) для сравнения между прогонами и
   с чужими работами; total return на разных горизонтах несопоставим.

## 7. Что взять за основу — короткий вывод

- **Измерение и валидация:** `freqtrade` (аудит look-ahead/recursive, учёт комиссий, p-value) +
  `crypto-quant-platform` (walk-forward + purge-gap + deflated Sharpe, издержки из конфига) как образец, а не
  как зависимость. Плюс репо Стефана Янсена как учебник по walk-forward и DSR.
- **Исполнение/микроструктура:** `nautilus_trader` (L2, queue, вероятностные филлы) — если стратегия
  действительно про стакан; `ccxt` — только как слой доступа к биржам.
- **Не брать:** `backtrader` (заброшен), «готовые прибыльные стратегии» из `freqtrade-strategies` (их там нет
  по замыслу), маркет-мейкинг Hummingbot (не тот профиль издержек: taker 0.05 % без ребейта убивает спред),
  и любые числа с Freqle / обзорных сайтов без методологии.
