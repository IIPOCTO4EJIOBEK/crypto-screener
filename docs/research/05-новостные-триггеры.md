# Новостные триггеры крипторынка: каналы, события, сверка с историей торговли

Дата: 29.09.2026. Часть проекта ИИ-скринера криптовалют. Задача раздела — не
перечислить «какие бывают новости», а выяснить, **что из новостного фона
доступно программно и с историческими метками времени**, чтобы это джойнилось
с историей свечей.

Пометки достоверности: `[A]` — есть первоисточник с числами (API проверен
вызовом, peer-reviewed работа или собственный замер по публичным данным);
`[B]` — вторичный источник / оценка практиков; `[C]` — общее мнение;
`[?]` — не подтверждено.

Все проверки доступа сделаны 29.09.2026 с этого хоста (10.1.222.71, Kali,
выход в сеть из РФ) — **с прокси из окружения и без него**. В каждом случае
приведён фактический HTTP-код, а не предположение.

---

## 0. Главный вывод раздела

Самый сильный новостной триггер в крипте — **анонсы бирж про листинг и
делистинг**, и именно по ним машинный доступ оказался лучше всего: у Binance,
Bybit, Upbit и OKX есть публичные JSON-эндпоинты без ключа, с epoch-метками
времени и с историей на годы назад. Всё остальное (агрегаторы, Telegram, X,
макро-календари) — ключ и деньги, отсутствие истории или гео-блок: общий
новостной поток как сигнал **менее ценен**, чем один биржевой анонс, потому
что метку времени и первоисточник по нему проверить нельзя.

Практический итог: у нас уже есть **2273 листинга и 438 делистингов Binance с
датами с 2017 года** `[A]` — этого хватает, чтобы измерить эффект самим, а не
верить чужим исследованиям.

### 1.2 Binance — самый полный источник `[A]`

`HTTP 200`, ключ не нужен, работает и с прокси, и без (но у Binance другие
эндпоинты с прокси ломаются, см. 1.9).

```
GET https://www.binance.com/bapi/composite/v1/public/cms/article/list/query
      ?type=1&pageNo={{N}}&pageSize={{M}}&catalogId={{ID}}
```

Каталоги (`catalogId`) и объёмы на 29.09.2026, все получены вызовом:

| catalogId | Название | Записей |
|---|---|---|
| 48 | New Cryptocurrency Listing | **2273** |
| 161 | Delisting | **438** |
| 157 | Maintenance Updates | 603 |
| 128 | Crypto Airdrop | 53 |
| 93 | Latest Activities | 3149 |
| 51 | API Updates | 81 |
| 49 | Latest Binance News | 4436 |

Поля статьи: `id`, `code`, `title`, `type`, `releaseDate` (epoch ms). Текст —
отдельным вызовом `.../article/detail/query?articleCode={{code}}` (rich-text JSON).

`pageSize=50` работает, `pageSize=100` → `HTTP 400` ⇒ **максимум 50 на
страницу**. Глубина проверена: `pageNo=50` даёт ноябрь 2023, `pageNo=114` —
июль 2017. **Полная история с 2017 достаётся пагинацией ~114 страниц по 20** —
~2300 запросов на весь корпус, однократно выполнимо.

Важно: `releaseDate` — **время публикации анонса, а не открытие торгов**.
Вторую метку («trading will open at ...») надо парсить из `body` `[B]`.

### 1.3 Bybit `[A]`

`HTTP 200`, ключ не нужен. **Требует доступа БЕЗ прокси**: через прокси
CloudFront отдаёт `403` «blocked access from your country» — выход прокси тоже
в закрытой стране.

```
GET https://api.bybit.com/v5/announcements/index?locale=en-US&limit=50&type=new_crypto
```

| `type` | Записей | | `type` | Записей |
|---|---|---|---|---|
| `new_crypto` | **1779** | | `product_updates` | 234 |
| `delistings` | **479** | | `maintenance` | 0 (пусто) |

Схема: `result.list[]` + `result.total`, поле времени `dateTimestamp` (epoch ms),
в элементе есть `title`, `type`.

### 1.4 OKX `[A]`

`HTTP 200`, ключ не нужен, работает и с прокси, и без.

```
GET https://www.okx.com/api/v5/support/announcements?annType={{T}}&page={{N}}
```

Живых значений `annType` оказалось **ровно два**; `announcements-latest`,
`-trading-suspensions`, `-withdrawals-suspensions`, `-coin-listing` и др. дают
`code 51000 «Parameter annType error»`:

| `annType` | Глубина |
|---|---|
| `announcements-new-listings` | `totalPage=5` (по 20) → ~100 |
| `announcements-delistings` | `totalPage=1` → 18 |

Поле времени — `pTime` (epoch ms). **История мелкая** — для глубокого прошлого
OKX не годится, но текущий поток даёт хорошо и служит быстрым дублем к Binance/Bybit.

### 1.5 Upbit `[A]`

`HTTP 200`, ключ не нужен.

```
GET https://api-manager.upbit.com/api/v1/announcements
      ?os=web&page={{N}}&per_page={{M}}&category={{trade|notice}}
```

| `category` | Записей |
|---|---|
| `trade` | **780** (листинги/торговые поддержки) |
| `notice` | 791 |

Поле времени — `listed_at` вида `2026-09-28T14:27:04+09:00` (**часовой пояс
+09:00, при джойне приводить к UTC**), есть также `first_listed_at`.
`category=listing` → `400`: категорий всего две. Корейские листинги Upbit дают
отдельный импульс, слабо связанный с Binance, поэтому это самостоятельный
канал, а не дубль `[B]`.

### 1.6 Bithumb, Coinbase, Telegram, X — что НЕ доступно

- **Bithumb** `[A]`: публичного JSON-эндпоинта анонсов **не нашлось**:
  `api.bithumb.com/v1/notices` → `302`, `www.bithumb.com/react/api/notices/notice`
  → HTML SPA. Без ключа работают только рыночные данные
  (`api.bithumb.com/public/ticker/ALL_KRW`, `/v1/market/all`). Анонсы — только
  скрап SPA, для конвейера не годится.
- **Coinbase** `[A]`: публичного API анонсов листингов **нет**:
  `blog.coinbase.com/feed` → `301`, `www.coinbase.com/blog/rss.xml` → `403`,
  `coinbase.com/blog/rss` → `403`. Листинги идут в блог и в X (@CoinbaseAssets) —
  машиночитаемо не отдаётся. Рабочий Statuspage (`status.coinbase.com/api/v2/summary.json`,
  `/incidents.json` — `200`, ISO-даты) даёт только техинциденты.
- **Telegram** `[A]`: `t.me/s/<канал>` отдаёт посты **только при включённом
  публичном предпросмотре**. Проверено: `t.me/s/watcherguru` → `200`, 18 постов;
  `t.me/s/tree_news`, `t.me/s/wublockchain`, `t.me/s/coindesk` → `302`
  (страница канала ~9 КБ, **без текста постов**). Истории постов превью не даёт
  вовсе. Полный путь — MTProto-клиент с `api_id/api_hash` на юзер-аккаунт
  (формально бесплатно, но это уже не «публичный доступ»).
- **X/Twitter** `[A]`: `api.twitter.com/2/tweets/search/recent` без токена →
  `401`; Nitter (`nitter.net`) → `000` (мёртв). Ленты бирж и основателей
  бесплатно **недоступны**.

### 1.7 Агрегаторы новостей `[A]`

| Сервис | Результат проверки |
|---|---|
| CryptoPanic `api/v1/posts` | `403` **и с прокси, и без** (Cloudflare); нужен `auth_token` |

| CoinGecko `/news` | `401` (Pro-ключ); `/ping` → `200`, рыночные данные бесплатны |

### 1.8 RSS изданий и макро `[A]`

**RSS без ключа** (`200`): `cointelegraph.com/rss` (30 свежих, первый от
29.09.2026 08:51 UTC), `www.theblock.co/rss.xml`, `decrypt.co/feed`,
`cryptoslate.com/feed/`, `news.bitcoin.com/feed/`,
`www.coindesk.com/arc/outboundfeeds/rss` (со слэшем на конце — `308`).
Не работают: `bitcoinmagazine.com/feed` → `403`. Ограничение RSS: окно **~30
последних материалов**, глубокой истории нет, а `pubDate` — время публикации
статьи, не события.

**Макро доступно лучше, чем ожидалось:**

- `api.bls.gov/publicAPI/v2/timeseries/data/` (POST, JSON) — `200` **без ключа**
  (незарегистрированный v2), отдаёт CPI и др. с периодами и значениями ⇒
  официальная инфляция программно и бесплатно `[A]`.
- `www.federalreserve.gov/feeds/press_monetary.xml` — `200`, RSS пресс-релизов
  ФРС, включая решения по ставке `[A]`.
- `api.stlouisfed.org/fred/...` — `400 «api_key is not set»`; **ключ бесплатный,
  но обязателен**, даёт полную историю макроданных с датами `[A]`.
- `nfs.faireconomy.media/ff_calendar_thisweek.json` — `200`, JSON-календарь
  событий (ForexFactory) без ключа, но **только текущая неделя** — истории нет `[A]`.
- SEC: `www.sec.gov/news/pressreleases.rss` → `200`, полнотекстовый поиск
  `efts.sec.gov/LATEST/search-index` → `200` (нужен User-Agent с контактом).
  Регуляторные события — программно и с датами `[A]`.

### 1.9 Сетевые грабли этого хоста (важно для реализации) `[A]`

Правило «прокси помогает» **неверно** — оно зависит от домена:

| Ресурс | с прокси | без прокси |
|---|---|---|
| `api.binance.com/api/v3/klines` | **451** (restricted location) | **200** |
| `www.binance.com/bapi/.../cms` | 200 | 200 |
| `api.bybit.com/v5/announcements` | **403** (CloudFront) | **200** |
| `www.okx.com/api/v5/support/...` | 200 | 200 |
| `api-manager.upbit.com` | 200 | 200 |
| `farside.co.uk/btc/` (ETF-потоки) | **200** | **403** |
| `cointelegraph.com/rss` | 200 | 200 (меньше материалов) |

Практический вывод: **для бирж прокси выключать** (его выход сам в закрытой
стране), **для Farside — включать**. Клиент новостного слоя должен ходить по
домену с прокси и без, а не использовать одну глобальную настройку. Это же
объясняет запись в `00-состояние.md` о «гео-блоке» Binance и Bybit: ключ там
был не при чём.

Публичное зеркало свечей — `data-api.binance.vision`: `200` и с прокси, и без,
история **с 2017-08-18** (проверено на `startTime=1502942400000`) `[A]`.

### 1.10 Данные помимо новостей `[A]`

- **Хаки/эксплойты:** `https://api.llama.fi/hacks` — `200`, **без ключа**,
  **1289 записей**. Поля: `date` (unix), `name`, `classification` (Governance /
  Access Control / Market Manipulation …), `technique`, `amount`, `chain`,
  `bridgeHack`, `source`, `returnedFunds`. Готовая база триггеров с датами.
- **Разлоки токенов:** `api.llama.fi/emissions` → **`402` (платно)**;
  TokenUnlocks/Tokenomist — только сайт. Бесплатного программного календаря
  разлоков **не нашлось**.
- **Опционы/волатильность:** Deribit public API без ключа — `get_book_summary_by_currency?currency=BTC&kind=option`
  → `200` (цепочка, OI), `get_volatility_index_data?currency=BTC&resolution=1D`
  → `200` (история DVOL; проверено на диапазоне с 2025-06, глубже не проверял).
- **CME:** публичного API нет, контекст только через Deribit.
- **ETF-потоки:** `farside.co.uk/btc/` — HTML-таблица, `200` через прокси,
  `403` напрямую ⇒ только скрап. Coinglass `open-api.coinglass.com` →
  `30001 «API key missing»`.

## 2. Классификация триггеров

Направление — ожидаемое; «характер» — категория, а не измеренная величина
(числа в разделе 3).

| # | Тип события | Направление | Характер реакции | Источник (машинно) |
|---|---|---|---|---|
| 1 | **Листинг на крупной бирже** | резко вверх | мгновенная, основное в первые минуты–часы | Binance 48, Bybit `new_crypto`, Upbit `trade`, OKX `new-listings` `[A]` |
| 2 | **Делистинг** | вниз | мгновенная, устойчивая (нет отскока) | Binance 161, Bybit `delistings`, Upbit `trade`, OKX `delistings` `[A]` |
| 3 | **Хак / эксплойт** | вниз | быстрая, но не всегда мгновенная (первая новость неточна) | DefiLlama `/hacks`, RSS, X `[A]` |
| 4 | **Регуляторика** (иск, санкции, одобрение/отказ ETF) | вниз при риске, вверх при одобрении | **двухфазная**: ожидание → «продавай на новости» | SEC RSS, Fed RSS, RSS изданий `[A]` |
| 5 | **Макро** (CPI, PPI, ставка FOMC) | зависит от **отклонения от консенсуса**, а не от факта | мгновенная, в момент публикации | BLS API, Fed RSS, FF-календарь `[A]` |
| 6 | **Институциональный поток** (ETF-притоки, крупные покупки) | по знаку потока | запаздывающая, копится днями | Farside (скрап) `[A]`/`[B]` |
| 7 | **Разлок токенов** | вниз (рост предложения) | **опережающая**: продают заранее | публичного API нет `[A]` |
| 8 | **Партнёрство / апгрейд сети** | вверх | чаще задержка: эффект на живом продукте | RSS, X, GitHub `[B]` |
| 9 | **Манипулятивный вброс** | любое | мгновенная и **ложная** — откат после опровержения | только X/Telegram `[B]` |

Уточнения, важные для реализации:

- **Тип 1.** Листинг — не один момент, а минимум **два**: публикация анонса и
  открытие торгов, между ними обычно часы `[B]`. Нужны обе метки, иначе импульс
  отнесётся не к той свече.
- **Тип 3.** Хак требует **двух источников**: первое сообщение в Telegram/X
  часто ошибочно в сумме и адресах `[B]`. DefiLlama даёт верифицированную
  запись, но с задержкой — это витрина, не лента `[B]`.
- **Тип 4.** Работает **на опережении**: рынок двигает ожидание (даты заседаний
  SEC и дедлайны по ETF известны заранее), а на самом объявлении фиксируют
  прибыль — пример в 3.2.
- **Тип 5.** Реагирует **не факт, а сюрприз** («вышло» − «ждали»). Без
  консенсус-прогноза знак реакции неизвестен `[B]`.
- **Тип 9.** Опасен именно для новостного слоя: сигнал выглядит настоящим, а
  первоисточника нет.

## 3. Что известно про сверку событий с историей торговли

### 3.1 Листинг: эффект есть, разброс огромен `[B]`

**Messari**, материал «The Crypto Exchange Pump Phenomenon» (аналитик Roberto
Talamas), в пересказе CoinDesk/Yahoo Finance: листинги на Coinbase дали
**средний рост +91% за первые пять дней торгов** при разбросе от **−32% до
+645%** (крайние точки — District0x +645%, Civic +493%). Размера выборки,
периода исследования и скорости затухания эффекта в пересказе **не приводится**
— этих данных нет.

Смысл: средний +91% при разбросе в сотни процентов означает, что «средний» тут
не работает. Эффект существует как **распределение с тяжёлым правым хвостом**,
а не как предсказуемая величина.

### 3.2 Регуляторный триггер: «продавай на новости» `[A]`

**Собственный замер** по дневным свечам BTCUSDT (`data-api.binance.vision`):

| Дата | Закрытие | Максимум дня | Примечание |
|---|---|---|---|
| 2024-01-10 | 46 654 | 47 696 | ожидание решения |
| **2024-01-11** | 46 339 | **48 969** | **день одобрения спот-ETF** |
| 2024-01-12 | 42 783 | 46 516 | **−7.67% к закрытию 11-го** |
| 2024-01-23 | 39 898 | — | минимум дня **38 555** |

От максимума дня одобрения (48 969) до минимума 23 января (38 555) — **−21.3%
за 12 дней**. Классическая форма «продавай на новости»: пик в день объявления,
дальше распродажа. Арифметика проверяема по публичным свечам `[A]`.

**Делистинг** `[B]` (кейс, не статистика): Monero — 6 февраля 2024 Binance
объявила о делистинге, цена упала примерно на **40% (выше $164 → $100) за 12
часов**, но к декабрю 2024 вернулась к ~$200, то есть выше уровня до делистинга
(источник — разбор rabbit.io, без методологии и размера выборки).

### 3.3 Хак: долгий ущерб `[A]`

Отчёт **Immunefi** (пересказ CoinMarketCap Academy): медианное падение цены
токенов после взлома/эксплойта — **−61% за шесть месяцев**; **83.9%**
пострадавших токенов остались ниже цены до хака на шестом месяце, восстановились
около 16%. Выборка: **425 публичных инцидентов**, **82 токена** отслежены по
цене, период **2021–2025**. Числа `[A]` (первичный отчёт не открывался).

Смысл: хак — не «отскок на следующий день», а **устойчивое повреждение** ⇒ для
скринера это сигнал исключения, а не точка входа.

### 3.4 Асимметрия: плохие новости двигают сильнее `[A]`

**Öget E., 2022**, *Journal of Research in Economics, Politics & Finance* 7(1):16–31,
DOI 10.30784/epfad.1011204. Метод — event study, окно события **(−5, +10)**;
изучены **листинг, делистинг, эйрдроп и принудительные меры SEC**. На уровне
значимости 1%: **22** значимых аномальных доходности у негативных событий
против **8** у позитивных; по накопленной аномальной доходности — **13** против **3**.
Вывод автора: после позитивных новостей о листинге прибыль стоит фиксировать
**в день анонса**, потому что «цены вернулись к равновесным к закрытию». `[A]`
(числа из аннотации; период выборки и число событий там не указаны — данных нет).

### 3.5 Делистинг иногда идёт ВВЕРХ — аномалия `[C]`

В поиске устойчиво всплывают разборы «почему монета растёт при анонсе
делистинга» (в т.ч. публикации Binance Square). Проверяемого объяснения с
числами найти не удалось; вероятная механика — снятие шортов на тонкой
ликвидности и панический откуп `[?]`. Для скринера вывод: **знак реакции на
делистинг нельзя постулировать, его надо проверять на своих данных.**

### 3.6 Макро: числа реакции не нашлось `[A]` для факта, `[?]` для связи

Текстовый источник (Binance Academy про CPI/PPI/ФРС) даёт **факты данных**, но
**никаких процентов движения крипты**: CPI августа 2026 — 0.4% м/м, 3.4% г/г;
PPI августа 2026 — 0.4% м/м, 5.4% г/г; FOMC 15–16 сентября 2026 повысил ставку
на 25 б.п., до 3.75–4.00%, единогласно. Свои тезисы («реакция на сюрприз»)
издание само помечает как тенденцию, а не правило `[B]`.

**Собственный замер** вокруг этого заседания (часовые свечи BTC: CoinGecko

### 3.7 Объём вокруг события — данных нет

Проверяемых исследований «как ведёт себя объём вокруг анонса листинга» с

## 4. Практический вывод для скринера

### 4.1 Что реально можно собрать

1. **Ядро — биржевые анонсы.** Четыре источника без ключа и с датами: Binance
   (2273/438, с 2017), Bybit (1779/479), Upbit (780 trade), OKX (~100/18, только
   свежие). Все — epoch ms или ISO, джойнятся со свечами `data-api.binance.vision` `[A]`.
2. **Хаки — `api.llama.fi/hacks`**: 1289 записей с датой, типом атаки, суммой и
   цепочкой. Готовая база триггера «эксплойт» `[A]`.
3. **Макро — BLS API (CPI без ключа), Fed RSS, FRED (бесплатный ключ),
   FF-календарь на текущую неделю** `[A]`. Для знака реакции нужен
   консенсус-прогноз, которого в бесплатных источниках нет.
4. **Опционы Deribit** (цепочка, OI, история DVOL) — контекст риска `[A]`.
5. **RSS изданий** — фон для отчёта человеку, не торговый сигнал `[A]`.
6. **ETF-потоки — скрап Farside через прокси**, раз в сутки `[A]`.

### 4.2 Что собрать нельзя

- **Coinbase** — ни листинги, ни блог машинно не отдаются (`403`/`301`) `[A]`.
- **Bithumb** — публичного API анонсов нет `[A]`.
- **X/Twitter и Telegram** — либо платно, либо не отдают историю `[A]`.
- **Календарь разлоков** — публичного API нет, DefiLlama emissions платный `[A]`.
- **CoinMarketCal, The Tie, LunarCrush, CryptoPanic** — ключ/деньги;
  CoinMarketCal вообще недоступен с этого хоста `[A]`.
- **Глубокая история OKX** — обрезана провайдером `[A]`.
- **Объём и скорость реакции на листинг** — только своими замерами.

### 4.3 Как отличить настоящую новость от вброса

1. **Первоисточник — только CMS биржи.** Настоящий листинг/делистинг существует
   как запись в официальном фиде (`releaseDate` + URL анонса); скриншот в
   Telegram — не событие. **Жёсткий фильтр: нет записи в официальном фиде →
   события нет**, и он проверяется автоматически, потому что фид у нас есть `[A]`.
2. **Правило двух источников** для всего, что не биржа: хак, партнёрство,
   регуляторное действие. Первое сообщение всегда самое неточное `[B]`.
3. **Проверка на обратимость.** Вброс откатывается после опровержения, значит
   нужна не только лента событий, но и лента «событие снято».
4. **Сверка знака с историей, а не с интуицией** (см. 3.5): знак реакции по
   типу события определяется **нашим замером на корпусе** — 438 делистингов
   дают достаточную выборку.
5. **Новостной слой — контекст, не сигнал.** Новость должна (а) блокировать
   вход (делистинг, хак, разлок — стоп-факторы), (б) повышать вес формации при
   подтверждающем событии, (в) снижать вес при необъяснённом движении. Торговля
   по заголовкам запрещена не из осторожности: **основная часть движения
   происходит до попадания новости в ленту** — в замере 3.2 пик был в день
   объявления, а лента отдаёт событие уже после начала движения `[A]`.
6. **Задержка источника = потеря импульса.** DefiLlama по хакам — витрина, не
   лента `[B]`; RSS — окно 30 материалов `[A]`; Upbit отдаёт `listed_at` уже
   состоявшегося листинга `[A]`. Опережения не даёт ничто из этого.

### 4.4 Минимальный конвейер

1. Опрос фидов (Binance 48/161, Bybit `new_crypto`/`delistings`, Upbit `trade`,
   OKX) раз в 1–5 минут, дедупликация по `id`/`code`/`uuid`.
2. Нормализация времени: `releaseDate`/`dateTimestamp`/`pTime`/`listed_at` → UTC epoch.
3. Хранение события: `источник`, `биржа`, `тип`, `ticker`, `время анонса`,
   `время открытия торгов`, `текст`, `URL` (проверяемый первоисточник).
4. Замер на истории: те же ключи против свечей `data-api.binance.vision` —
   частоту и разброс реакции по типу события считаем **сами**.
5. Записи без распознанного первоисточника — в карантин, не в сигналы.
