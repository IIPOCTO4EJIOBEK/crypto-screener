# Состояние проекта: доступы и данные

Дата: 29.09.2026. Файл фиксирует, что установлено проверками, а что осталось
неизвестным. Ключей здесь нет — они в `.env`.

---

## 1. Ключи брокера: что это

Пользователь передал пару ключей (по 64 символа) со словом «ключи брокера»
и ссылкой на страницу их создания — `https://account.tiger.com/api`.

`account.tiger.com` — это **Tiger.com Broker**, сервис-прослойка (сайт
хостится в Selectel, Санкт-Петербург). Из их документации
(`broker-docs.tiger.com`, страница «Creating API keys»):

> API keys generated in Tiger.com Broker are identical to those created
> directly on exchanges. This means you can use them seamlessly in the
> Tiger.com terminal or with other applications.

То есть ключи, созданные в кабинете Tiger, должны быть обычными ключами
биржи. Tiger создаёт ключи для **Binance, Bybit, Gate.io**; отдельно есть
**TigerX** — собственный коннектор к Binance и OKX, работающий через их
инфраструктуру.

---

## 2. Какие биржи проверены и с каким итогом

Проверка подписанными запросами (ccxt и ручной HMAC там, где ccxt требует
passphrase, которой у нас нет).

| Биржа | Ответ | Что это значит |
|---|---|---|
| Binance | HTTP 451 | отказ по геолокации (РФ), ключ не проверен |
| Bybit | HTTP 403 | блок по стране (CloudFront), ключ не проверен |
| Gate.io | 401 `INVALID_KEY` | подпись **принята**, ключ чужой — не Gate |
| OKX, Bitget, KuCoin, Weex | требует passphrase | у нас её нет, проверить нельзя |
| MEXC | `10072 Api key info invalid` | не MEXC |
| BingX | `100413 Incorrect apiKey` | не BingX |
| XT | `AUTH_101` | не XT |
| CoinEx | `access_id not exists` | не CoinEx |
| Poloniex | `Invalid Apikey or Signature` | не Poloniex |
| Bitvavo | `305 No active API key found` | не Bitvavo |
| Backpack | `INVALID_CLIENT_REQUEST` | не Backpack |
| HTX, LBank, Phemex, Toobit | не проверены надёжно | таймаут при пробе, нужен повтор |

**Итог: биржа не определена.** Наиболее вероятны Binance или Bybit —
единственные, которые не удалось проверить из-за гео-блока, — либо ключ
относится к TigerX и работает только внутри терминала Tiger for Windows
7.0+ (их публичного REST для TigerX нет).

Проще всего выяснить точно: в кабинете на `account.tiger.com/api` у ключа
видно, к какой бирже он относится (вкладки Binance / Bybit / Gate.io /
Tiger X).

---

## 3. Ключ для скринера не нужен

Это главное, что снимает блокировку: **стакан, свечи и лента сделок —
публичные данные**, приватный ключ для них не требуется. Ключ нужен только
для баланса, позиций и выставления заявок — это отдельный, более поздний
слой.

---

## 4. Что доступно с хоста

Отдельная находка: **прокси из окружения** (`HTTP_PROXY` =
`http://23.236.152.19:9177`) режет часть доменов по таймауту. Без прокси те
же адреса отвечают за доли секунды. Проверено напрямую:

| Домен | Ответ |
|---|---|
| `api.gateio.ws` | 200, данные отдаёт (BTC/USDT = 83773.9) |
| `www.okx.com` | 200 |
| `api.mexc.com` | 404 на корне, API живой |
| `api.huobi.pro` | 404 на корне, API живой |
| `api.lbank.info` | 200 |
| `api.phemex.com`, `api.toobit.com` | 404 на корне, живы |
| `api.binance.com` | 403 без прокси, 451 через прокси — **недоступен** |

Вывод для сбора данных: обращаться к биржам, минуя прокси
(`NO_PROXY='*'`), либо перечислить их в `no_proxy`.

### 4.1. Данные Binance и Bybit всё-таки доступны

Отдельная проверка, снимающая главное ограничение. Гео-блок накрывает
**торговый** домен Binance (`api.binance.com`), но не публичный
market-data:

| Что | Адрес | Ответ |
|---|---|---|
| Binance, свечи 1m | `data-api.binance.vision/api/v3/klines` | 200, данные идут |
| Binance, стакан | `data-api.binance.vision/api/v3/depth` | 200, данные идут |
| Bybit, свечи | `api.bybit.com/v5/market/kline` | 200 (`retCode:0`) |
| Bybit, стакан | `api.bybit.com/v5/market/orderbook` | 200 (`retCode:0`) |
| OKX, стакан | `www.okx.com/api/v5/market/books` | 200 |

Проверено на BTC/USDT 29.09.2026: Binance — 83 780.58, Bybit — 83 785.0,
OKX — 83 794.5.

**Что это значит для проекта:**

- скринер строится на **реальных данных Binance, Bybit и OKX** — тех самых
  биржах, что и в Tiger, а не на суррогате;
- для этого не нужен ни ключ, ни прокси: данные публичные, обращение
  напрямую;
- приватный ключ нужен только под баланс, позиции и заявки, и его биржа
  по-прежнему не определена (раздел 2) — но это уже не мешает собирать и
  анализировать рынок.

## 5. Оговорка по безопасности

Ключи были переданы в переписке, то есть считаются скомпрометированными.
Они read-only (без права вывода), но их следует **перевыпустить** после
того, как схема доступа будет настроена. В репозиторий они не попадают:
`.env` в `.gitignore`.
